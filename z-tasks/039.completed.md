# Task 039: Port CLI Browse Commands (M-12.8)

## Objective
Wire the browse-related CLI subcommands (artists, genres, labels, descriptors) to rose-core query and dump functions.

## Context
Rose is a music library manager being migrated from Python to Rust. The browse commands let users print individual or all artists/genres/labels/descriptors as JSON. Each entity type has two subcommands: `print` (single) and `print-all` (list all). These are thin wrappers around the dump module.

## Constraints Relevant to This Task
- These are four separate subcommand groups (`rose artists`, `rose genres`, `rose labels`, `rose descriptors`), each with `print` and `print-all`.
- Arguments are plain name strings (not UUIDs or paths).

## Prior Work
From task 033, dump functions exist:
- `dump_artist(c, name) -> Result<String>`, `dump_all_artists(c) -> Result<String>`
- `dump_genre(c, name) -> Result<String>`, `dump_all_genres(c) -> Result<String>`
- `dump_label(c, name) -> Result<String>`, `dump_all_labels(c) -> Result<String>`
- `dump_descriptor(c, name) -> Result<String>`, `dump_all_descriptors(c) -> Result<String>`

## Files to Read
- `rose-cli/rose_cli/cli.py` lines 559–637 — Python browse commands
- `rose-rs/rose-cli/src/main.rs` — current stubs
- `rose-rs/rose-cli/src/dump.rs` — dump functions

## What to Implement

#### `rose artists print <ARTIST>`
Print a single artist as JSON (with roles). Calls `dump_artist(c, name)`.

#### `rose artists print-all`
