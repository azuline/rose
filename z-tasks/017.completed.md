# Task 017: Cache Update — Source Directory Renaming (M-7.1d)

## Objective
Implement stage 4 of the cache update pipeline: rename source release directories and track files to match path templates when `config.rename_source_files` is enabled. Handle collisions and update in-memory paths.

## Context
Rose is a music library manager being migrated from Python to Rust. When `rename_source_files` is enabled in config, the cache update renames release directories and track files to match configured path templates. This ensures the source directory structure stays organized according to user preferences.

**Pipeline overview:**
1. Task 014: Scan directories → `Vec<ScannedRelease>`
2. Task 015: Compare mtimes → `Vec<CacheCandidate>`
3. Task 016: Read tags → `Vec<PreparedRelease>`
4. **This task (017):** Rename directories/files → mutated `Vec<PreparedRelease>`
5. Task 018: Batch SQL writes

## Constraints Relevant to This Task
- Only rename if `config.rename_source_files` is `true`.
- Only rename if the release is dirty (metadata changed).
- Directory rename collision: append ` [N]` suffix (starting at 2), respecting `config.max_filename_bytes`.
- File rename collision: same ` [N]` pattern, preserving file extension.
- After renaming a directory, update ALL in-memory paths: `release.source_path`, `release.cover_image_path`, all `track.source_path` + re-read their mtimes.
- After renaming a track file, clean up empty parent directories left behind.
- String comparison for "do we need to rename": use raw equality (Python's `_compare_strs` is currently just `==`, NFC normalization is commented out).
- `sanitize_dirname` and `sanitize_filename` with `strip_parens=true` and `sanitize_diacritics=true`.

### Function

**`rename_source_files(config, prepared: &mut Vec<PreparedRelease>) -> Result<()>`**

For each `PreparedRelease` where `config.rename_source_files` is true:

1. **Directory rename** (only if `release_dirty`):
   - Compute `wanted_dirname = evaluate_release_template(config.path_templates.source.release, &release)`.
   - Sanitize: `sanitize_dirname(config, &wanted_dirname, true)` with diacritics sanitization.
   - Collision loop: while `wanted_dirname != release.source_path.file_name()`:
     - If `source_path.with_file_name(wanted_dirname)` exists → bump collision counter, truncate dirname to fit `max_filename_bytes - len(" [N]")`, retry.
     - Otherwise → `std::fs::rename(old, new)`. Log the rename.
     - Update `release.source_path` to new path.
     - Update `release.cover_image_path`: rebase relative to new path.
     - Update all `track.source_path`: rebase relative to new path, re-stat for mtime, add to `track_ids_to_insert`.

2. **Track file rename** (only for tracks in `track_ids_to_insert`):
   - Compute `wanted_filename = evaluate_track_template(config.path_templates.source.track, &track)`.
   - Sanitize: `sanitize_filename(config, &wanted_filename, true)` with diacritics sanitization.
   - Collision loop (same pattern): compare relative path from release dir.
     - Truncate stem (not extension) to fit `max_filename_bytes - len(" [N]") - len(ext)`.
   - After rename, clean up empty parent directories (walk up relative path).

### Data flow to next stage
The `Vec<PreparedRelease>` is mutated in-place (paths updated). Passed directly to task 018 for SQL writes.

### Function signature

```rust

    config: &Config,
    prepared: &mut [PreparedRelease],
```

Matches the spec exactly. Takes a mutable slice and mutates in-place.

### Helper functions added

- **`cache_release_to_template(r: &Release) -> templates::Release`** — converts the `cache::Release` struct to the `templates::Release` struct for template evaluation. Required because the two modules have separate (but structurally identical) Release types.
- **`cache_track_to_template(t: &Track) -> templates::Track`** — same conversion for tracks.
- **`truncate_utf8_public(s, max_bytes) -> &str`** — public wrapper around the existing `truncate_utf8` in `common.rs`, needed for collision suffix truncation in the rename logic.

### Behavior

1. **Early return if disabled**: If `config.rename_source_files` is false, the function returns immediately without touching any files.

2. **Directory rename** (only if `release_dirty`):
   - Evaluates `config.path_templates.source.release` with the release metadata.
   - Sanitizes via `sanitize_dirname(max_filename_bytes, wanted, true, true)` — enforces max length and strips diacritics.
   - Collision loop: if the desired name already exists on disk, appends ` [N]` suffix (N starting at 2), truncating the original name to fit within `max_filename_bytes`.
   - After `std::fs::rename`, updates `release.source_path`, `release.cover_image_path` (rebased via `strip_prefix`), and all `track.source_path` values. Re-reads mtime for each track. Adds all track IDs to `track_ids_to_insert`.

3. **Track file rename** (only for tracks in `track_ids_to_insert` at the time the loop starts):
   - Evaluates `config.path_templates.source.track` with track metadata.
   - Sanitizes via `sanitize_filename(max_filename_bytes, wanted, true, true)`.
   - Collision loop: truncates the stem (preserving extension) and appends ` [N]` suffix.
   - Creates parent directories if the template produces nested paths.
   - After rename, cleans up empty parent directories by walking up the relative path.

### Collision handling

Follows the Python implementation exactly:
- Directory collisions: `original_wanted_dirname[:max_len] [N]` where `max_len = max_filename_bytes - len(" [N]")`.
- Track file collisions: `original_stem[:max_len] [N].ext` where `max_len = max_filename_bytes - len(" [N]") - len(".ext")`.
- Collision counter starts at 2 and increments until a non-conflicting name is found.

### String comparison

Uses raw `==` equality (matching Python's `_compare_strs` which currently has NFC normalization commented out). The `sanitize_dirname`/`sanitize_filename` functions already NFC-normalize their output, so the comparison is between NFC-normalized wanted names and filesystem names.
