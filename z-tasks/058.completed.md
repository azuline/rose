# Task 058: Config — Type Validation Error Tests (T-3.1)

## Objective
Add Rust tests for config type validation errors across all fields, matching the breadth of Python's `test_config_value_validation` and `test_vfs_config_value_validation`.

## Context
Python has two monolithic validation tests that check ~60 individual invalid-type scenarios (e.g. `music_source_dir = 123`, `cover_art_stems = "lalala"`, `vfs.artists_whitelist = [123]`). The Rust config tests have 29 tests but only cover a handful of type-validation paths. Many invalid types may be caught by serde deserialization, but this should be verified with explicit tests.

## Completed

All 17 tests implemented and passing. All errors are caught by **custom validation** in `Config::parse()`, not by serde. The Rust config parser does not use serde for deserialization — it parses the TOML into a raw `toml::Table` and manually extracts/validates each field with match arms on `TomlValue` variants. This means every type error is caught by our hand-written validation code and produces a `RoseError::InvalidConfigValue` with a descriptive message.
