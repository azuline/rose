# Task 043: Port File Watcher with Debouncing (M-13.1)

## Objective
Port the file watcher from Python's `watchdog` to Rust's `notify` crate, with a debounced async event processing pipeline integrated into the CLI.

## Context
Rose is a music library manager being migrated from Python to Rust. The file watcher monitors the music source directory for changes and triggers targeted cache updates. It is architecturally decoupled into a sync filesystem event listener (notify thread) and an async event processor with debouncing to avoid redundant cache updates when many files change simultaneously (e.g., copying a 20-track album triggers 20+ events but should result in one cache update).

## Constraints Relevant to This Task
- **Architecture:** Sync `notify` watcher thread pushes events into a channel. An async consumer (tokio or a dedicated thread with crossbeam) debounces and dispatches cache updates.
- **Debounce parameters:**
  - 200ms dedup window: events with the same hash within 200ms are dropped.
  - 2s delay for release events: after receiving a release event, wait 2 seconds before processing (to let multi-file copies complete). Collage/playlist events process immediately.
- **Event classification:** Parse the changed path relative to `music_source_dir`:
  - `!collages/*.toml` → collage event with collage name
  - `!playlists/*.toml` → playlist event with playlist name
  - First path component → release event with release directory path
- **Event types:** created, deleted, modified, moved. "Moved" = update + evict.
- **Daemonization:** Reuse `daemonize()` from task 041. PID file at `config.watchdog_pid_path`.
- **SIGTERM handler:** Graceful shutdown of both the watcher thread and event processor.
- **Stale PID cleanup:** On `unwatch`, check if the PID file process is alive; clean up if stale.

### 1. Event Types

```rust
enum EventType { Created, Deleted, Modified, Moved }

enum WatchEvent {
    Collage { name: String, event_type: EventType },
    Playlist { name: String, event_type: EventType },
    Release { dir: PathBuf, event_type: EventType },
}
```

### 2. Event Classifier
Classify `notify::Event` into `WatchEvent` by parsing the path relative to `music_source_dir`:
- Strip the source dir prefix to get the relative path.
- If starts with `!collages/` and ends with `.toml`: collage event.
- If starts with `!playlists/` and ends with `.toml`: playlist event.
- Otherwise: take first path component as release directory.
- Map notify event kinds to EventType (Create→Created, Remove→Deleted, Modify→Modified, Rename→Moved).

### 3. Debounced Event Processor
Use either tokio or a dedicated thread with crossbeam-channel:

```rust
async fn event_processor(config: &Config, rx: Receiver<WatchEvent>) {
    let mut debounce_times: HashMap<u64, Instant> = HashMap::new();
    loop {
        // Poll for events with timeout
        match rx.try_recv() {
            Ok(event) => {
                let key = hash(&event);
                if let Some(last) = debounce_times.get(&key) {
                    if last.elapsed() < Duration::from_millis(200) {
                        continue; // Skip debounced event
                    }
                }
                debounce_times.insert(key, Instant::now());

                match &event {
                    WatchEvent::Collage { .. } | WatchEvent::Playlist { .. } => {
                        handle_event(config, &event, None).await;
                    }
                    WatchEvent::Release { .. } => {
                        // Spawn with 2s delay
                        tokio::spawn(handle_event(config, event, Some(Duration::from_secs(2))));
                    }
                }
            }
            Err(_) => sleep(Duration::from_millis(500)).await,
        }
    }
}
```

### 4. Event Handler
```rust
async fn handle_event(config: &Config, event: &WatchEvent, delay: Option<Duration>) {
    if let Some(d) = delay { sleep(d).await; }
    match event {
        // Created/Modified → update cache for that entity
        // Deleted → evict nonexistent
        // Moved → update + evict
    }
}
```

### 5. Watcher Setup
```rust
fn start_watcher(config: &Config) -> Result<()> {
    let (tx, rx) = channel();
    let mut watcher = notify::recommended_watcher(move |res| { /* classify and send */ })?;
    watcher.watch(&config.music_source_dir, RecursiveMode::Recursive)?;
    // Run event processor (blocking)
    event_processor(config, rx);
}
```

### 6. CLI Subcommands

#### `rose cache watch [--foreground]`
1. Load config.
2. If not `--foreground`: call `daemonize(Some(&config.watchdog_pid_path))`.
3. Call `start_watcher(&config)`.

#### `rose cache unwatch`
1. Load config.
2. If PID file doesn't exist: log "No known watchdog running", exit 1.
3. Read PID from file.
4. Send SIGTERM to the PID (`nix::sys::signal::kill(pid, SIGTERM)`).
5. Log "Killed watchdog at process {pid}" (or "Process {pid} not found" if dead).
6. Delete the PID file.
