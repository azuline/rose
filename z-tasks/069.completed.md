# Task 069: Common — Missing Unit Tests (T-10.1)

## Objective
Add Rust tests for `ArtistMapping::dump()`, `sanitize_filename` diacritics stripping, `RoseError::is_expected()` behavior, and SHA-256 hashing of nested structures.

## Context
The Rust common module has 13 tests but misses a few behaviors tested in Python or expected by other modules: dump serialization, filename (vs dirname) diacritics handling, error classification, and hash stability for complex nested data.

## Files to Read
- `rose-rs/rose-core/src/common.rs` — Rust implementation + tests (tests start ~line 332)
- `rose-py/rose/common.py` — Python implementation
- `rose-py/rose/common_test.py` — Python test: `test_sanitize_diacritics`

## What to Implement

Add the following tests to `rose-rs/rose-core/src/common.rs`:

1. **`test_sanitize_filename_diacritics`** — Call `sanitize_filename` with `"Préludes.flac"` and `sanitize_diacritics=true`. Assert output is `"Preludes.flac"` (diacritics stripped, extension preserved).

2. **`test_artist_mapping_dump`** — Create an ArtistMapping with artists in multiple roles. Call `dump()` (or the serde equivalent). Assert the output is a dict/map with all 7 role keys, each containing the expected artist names.

3. **`test_rose_error_is_expected`** — Construct different `RoseError` variants. Assert that user-facing errors (e.g. `CollageAlreadyExists`) return `is_expected() == true`, while internal errors return `false`.

4. **`test_sha256_nested_structure`** — Create a complex struct with nested fields (e.g. an ArtistMapping inside a larger struct). Hash it twice. Assert both hashes are identical (determinism). Modify one field. Assert the hash changes.

5. **`test_sha256_empty_vs_populated`** — Hash an empty ArtistMapping and a populated one. Assert they produce different hashes.
