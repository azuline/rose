# Task 049: Update Nix Build (M-15.3)

## Objective
Update `flake.nix` to build the Rust crates (rose-cli, rose-vfs, rose-py) using Nix, replacing or supplementing the old Python package definitions.

## Context
Rose is a music library manager migrated from Python to Rust. The existing `flake.nix` builds 4 Python packages (rose-py, rose-watch, rose-vfs, rose-cli) using `buildPythonPackage`. The Rust implementation lives in `rose-rs/` as a Cargo workspace. This task updates the Nix build to produce Rust binaries and the PyO3 extension module.

## Constraints Relevant to This Task
- The Rust workspace is at `rose-rs/` with members: `rose-core`, `rose-cli`, `rose-vfs`, `rose-py`.
- The PyO3 crate (`rose-py`) produces a `.so` that needs to be importable by Python — this requires special Nix handling.
- Choose one Rust-in-Nix strategy: `crane`, `naersk`, or `pkgs.rustPlatform.buildRustPackage`. All three work; `crane` is the most popular for flakes.
- Keep the dev shell functional with both Rust and any remaining Python tooling.
- The `all` output should now include the Rust binaries.
- `fuser` crate (used by rose-vfs) links against `libfuse` — this is a native dependency that must be provided.
- `rusqlite` with `bundled` feature compiles SQLite from source — no external dep needed.

## Prior Work
The existing `flake.nix` defines:
- `devShells.default` — includes Python, Rust toolchain (rustc, cargo, rustfmt, clippy, rust-analyzer), ruff, prettier, pyright.
- `packages.rose-py`, `packages.rose-watch`, `packages.rose-vfs`, `packages.rose-cli` — Python packages.
- `packages.all` — combined environment of all 4 Python packages.
- Uses `nixpkgs` (unstable) and `flake-utils`.

## Files to Read
- `flake.nix` (current Nix configuration — 136 lines)
- `rose-rs/Cargo.toml` (workspace definition and members)
- `rose-rs/rose-core/Cargo.toml` (native deps: rusqlite bundled)
- `rose-rs/rose-vfs/Cargo.toml` (native deps: fuser -> libfuse)
- `rose-rs/rose-py/Cargo.toml` (PyO3 extension module)

## What to Implement

Edit `flake.nix`:

1. **Add a Rust build input** (if using `crane`):
   ```nix
   inputs.crane.url = "github:ipetkov/crane";
   ```
   Or use `pkgs.rustPlatform.buildRustPackage` (no extra input needed).

2. **Define Rust package builds:**
   - `rose-cli-rs` — the main CLI binary. Native deps: `pkg-config`, `fuse` (for the VFS subcommand if CLI embeds VFS).
   - `rose-vfs-rs` — the FUSE binary. Native deps: `fuse`/`fuse3`.
   - `rose-py-rs` — the PyO3 module. Needs `python3` and `maturin` or manual `.so` installation.
   - Alternatively, build the entire workspace and split outputs.

3. **Handle native dependencies:**
   ```nix
   nativeBuildInputs = [ pkgs.pkg-config ];
   buildInputs = [ pkgs.fuse ] 
     ++ pkgs.lib.optional pkgs.stdenv.isDarwin pkgs.macfuse-stubs;
   ```

4. **PyO3 special handling:**
   - Set `PYO3_PYTHON` to point to the Nix Python interpreter.
   - The output `.so` needs to be placed where Python can find it, or wrapped into a Python package.

5. **Update `packages.all`** to include Rust binaries instead of (or alongside) Python packages.

6. **Update dev shell** if needed — it already has Rust tools, but may need `pkg-config` and `fuse` headers for `cargo build` to work.

7. **Keep old Python packages** temporarily (they're deleted in task 051). Mark them with a comment `# TODO: Remove after Python deletion`.
