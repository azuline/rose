# Task 032: Create rose-cli Crate (M-12.1)

## Objective
Create the `rose-cli` binary crate with clap-derive command structure, lazy config loading, and `rose version` as the only implemented subcommand.

## Context
Rose is a music library manager for Unix being migrated from Python to Rust. The CLI is a thin layer over `rose-core` — all business logic already exists. This task scaffolds the binary crate and defines all subcommand groups (releases, tracks, collages, playlists, artists, genres, labels, descriptors, rules, cache, fs, config) but only implements `rose version`.

## Constraints Relevant to This Task
- Use `clap` with derive macros for all argument parsing.
- `--verbose`/`-v` global flag sets `tracing` to DEBUG level (default: INFO).
- `--config`/`-c` optional global flag overrides the config file path.
- **Lazy config loading:** Do NOT parse config for `rose version`. Python eagerly parses config on every invocation including `rose version` — this is a quirk NOT to reproduce. Config should only be loaded when a subcommand actually needs it.
- The binary name is `rose`.

## Prior Work
The full `rose-core` library exists from tasks 001–031 with all modules: common, genre_hierarchy, audiotags, rule_parser, templates, config, cache, rules, releases, tracks, collages, playlists. The `rose-vfs` binary crate also exists.

Key types/functions available in `rose-core`:
- `Config::load(path: Option<&Path>) -> Result<Config>`
- `common::VERSION: &str`
- All CRUD functions (releases, tracks, collages, playlists, rules, cache)

### 4. Lazy config helper
Create a helper that loads config on first access:
```rust
fn load_config(config_path: &Option<PathBuf>) -> Result<Config> {
    Config::load(config_path.as_deref())
}
```
Subcommand stubs that need config should call this; `version` should NOT.

### 5. Tracing initialization
In `main()`, before dispatching subcommands, init tracing-subscriber with level based on `--verbose`.
