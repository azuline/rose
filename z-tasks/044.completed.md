# Task 044: Create rose-py PyO3 Crate, Expose Config (M-14.1)

## Objective
Create a new `rose-rs/rose-py/` crate using PyO3 that exposes the Rust `Config` type to Python, allowing `import rose; c = rose.Config.load("/path/to/config.toml")`.

## Context
Rose is a music library manager being migrated from Python to Rust. The entire Rust implementation now exists in `rose-rs/` (rose-core library, rose-vfs FUSE binary, rose-cli CLI binary). A permanent PyO3 scripting shim is required so Python scripts can call into the Rust library. This task creates that crate and exposes the first type: `Config`.

## Constraints Relevant to This Task
- The PyO3 module name must be `rose` so that `import rose` works from Python.
- This is a thin wrapper — no business logic in this crate, only `#[pyclass]`/`#[pymethods]` wrappers around `rose-core` types.
- Use `pyo3` with the `extension-module` feature.
- The crate type must be `cdylib` for building a Python extension module.
- Error handling: convert `rose-core` errors into Python exceptions using `PyErr`.

## API to Produce
```python
# Python usage:
import rose

config = rose.Config.load("/path/to/config.toml")
print(config.music_source_dir)
print(config.fuse_mount_dir)
print(config.cache_dir)
```

```rust
// Rust side:
#[pyclass(name = "Config")]
pub struct PyConfig { inner: rose_core::Config }

#[pymethods]
impl PyConfig {
    #[classmethod]
    fn load(_cls: &Bound<'_, PyType>, path: &str) -> PyResult<Self>;

    #[getter]
    fn music_source_dir(&self) -> String;
    #[getter]
    fn fuse_mount_dir(&self) -> String;
    #[getter]
    fn cache_dir(&self) -> String;
}

#[pymodule]
fn rose(m: &Bound<'_, PyModule>) -> PyResult<()>;
```

## Completed

### PyConfig wrapper pattern
- `PyConfig` wraps `rose_core::config::Config` in `inner: rose_core::config::Config`.
- `#[pyclass(name = "Config")]` exposes it as `rose.Config` in Python.
- `#[classmethod] fn load(path: Option<&str>)` calls `Config::parse()` — accepts `None` for the default XDG path.
- Read-only `#[getter]` methods expose: `music_source_dir`, `fuse_mount_dir` (from `vfs.mount_dir`), `cache_dir`, `max_proc`, `rename_source_files`, `max_filename_bytes`, `cover_art_stems`, `valid_art_exts`, `write_parent_genres`, `ignore_release_directories`.

### Error conversion approach
- A single `fn to_pyerr(e: RoseError) -> PyErr` converts all `rose_core::common::RoseError` variants to `pyo3::exceptions::PyRuntimeError` using `e.to_string()`.

### PyO3 version-specific decisions
- Using `pyo3 0.22` with `extension-module` feature.
- Explicit `#[pyo3(signature = ...)]` attributes used on all functions with `Option<T>` trailing parameters to avoid the deprecated implicit-defaults behavior.
- `#![allow(clippy::useless_conversion)]` at crate level to suppress false positives from PyO3 macro expansions.
