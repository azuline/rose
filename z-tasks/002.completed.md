# Task 002: Port common.rs (M-1.2)

## Objective
Port the common utilities module from Python to Rust, including error types, the `Artist`/`ArtistMapping` types, filesystem sanitization functions, and helper utilities.

## Context
Rose is a music library manager being migrated from Python to Rust. The `common` module is the foundational grab-bag used by every other module. It contains types, error hierarchy, and utility functions.

## Constraints Relevant to This Task
- **Path normalization:** Do NOT normalize paths to NFC for comparison (match Python, which compares raw OS bytes). `sanitize_dirname`/`sanitize_filename` apply NFC on *output* only. Python has NFC normalization commented out in `_compare_strs()` (`cache.py:2535`).
- **Feature parity required:** Every capability in Python must exist in Rust.

- Dependencies available: `serde`, `sha2`, `regex`, `unicode-normalization`, `tracing`, `thiserror`.

## What to Implement

### Error types (`RoseError`)
Port as a `thiserror` enum. At minimum:
- `RoseError` with variants for expected errors (printed without traceback) and internal errors.
- Specific variants: `GenreDoesNotExist`, `LabelDoesNotExist`, `DescriptorDoesNotExist`, `ArtistDoesNotExist`.
- The Python pattern has `RoseExpectedError` as a subclass — model this with an `is_expected()` method or a trait.

### `ArtistMapping` struct
Fields: `main`, `guest`, `remixer`, `producer`, `composer`, `conductor`, `djmixer` — each `Vec<Artist>`.
Methods:
- `all(&self) -> Vec<&Artist>` — deduplicated union of all roles, preserving order (main, guest, remixer, producer, composer, conductor, djmixer).
- `dump(&self)` — serialize to a serde-compatible representation.
- `items(&self) -> Vec<(&str, &[Artist])>` — yields `("main", &self.main)`, etc.
- `Default` impl with empty vecs.

### `sanitize_dirname(max_filename_bytes: usize, name: &str, enforce_maxlen: bool, sanitize_diacritics: bool) -> String`
- Replace `ILLEGAL_FS_CHARS_REGEX` matches with `_`.
- If `enforce_maxlen`: truncate UTF-8 to `max_filename_bytes` bytes at a char boundary, then `.trim()`.
- If `sanitize_diacritics`: NFD decompose, strip combining chars.
- Always: NFC normalize the output.

### `sanitize_filename(max_filename_bytes: usize, name: &str, enforce_maxlen: bool, sanitize_diacritics: bool) -> String`
Same as `sanitize_dirname` but preserves file extension. If extension is >6 bytes, treat it as part of the stem.

### `sha256_dataclass` equivalent
`pub fn sha256_struct(value: &impl Serialize) -> String` — deterministic SHA-256 of a serde-serializable value. Use `serde_json::to_string` for canonical form, then SHA-256 the bytes.

### Utility functions
- `pub fn flatten<T>(xxs: Vec<Vec<T>>) -> Vec<T>`
- `pub fn uniq<T: Eq + Hash + Clone>(xs: Vec<T>) -> Vec<T>` — preserves first-occurrence order.

### Constants
- `pub const VERSION: &str = "..."` — match the value in `rose-py/rose/.version`.
- `pub static ILLEGAL_FS_CHARS_REGEX: Lazy<Regex>` — pattern: `[:\?<>\\*\|"\/]+`

## Tests to Write
1. **Illegal chars:** `sanitize_dirname` replaces `:?<>\\*|"/` with `_`.
2. **Max-length truncation:** Truncate at byte boundary (e.g., a multi-byte char at boundary 180 must not produce invalid UTF-8).
3. **Diacritics stripping:** `"Modéré"` with `sanitize_diacritics=true` becomes `"Modere"`.
4. **NFC output:** Output is always NFC-normalized.
5. **Empty input:** `sanitize_dirname("", ...)` returns `""`.
6. **Extension preservation:** `sanitize_filename("foo:bar.mp3", ...)` keeps `.mp3`.
7. **Long extension ignored:** Extensions >6 bytes are treated as part of the stem.
8. **`ArtistMapping::all()` dedup:** Artists appearing in multiple roles appear only once in `all()`.
9. **Hash determinism:** Same struct produces same hash across calls.
10. **`uniq` preserves order:** `[3, 1, 2, 1, 3]` -> `[3, 1, 2]`.

## Completed

### Actual Public API Created

```rust
// rose-core/src/common.rs

// Constants
pub const VERSION: &str = "0.5.0";
pub static ILLEGAL_FS_CHARS_REGEX: LazyLock<Regex>;

// Error types
pub enum RoseError {
    GenreDoesNotExist(String),
    LabelDoesNotExist(String),
    DescriptorDoesNotExist(String),
    ArtistDoesNotExist(String),
    Internal(String),
}
impl RoseError {
    pub fn is_expected(&self) -> bool;
}

// Artist types
pub struct Artist { pub name: String, pub alias: bool }
impl Artist {
    pub fn new(name: impl Into<String>) -> Self;
}

pub struct ArtistMapping {
    pub main: Vec<Artist>,
    pub guest: Vec<Artist>,
    pub remixer: Vec<Artist>,
    pub producer: Vec<Artist>,
    pub composer: Vec<Artist>,
    pub conductor: Vec<Artist>,
    pub djmixer: Vec<Artist>,
}
impl ArtistMapping {
    pub fn all(&self) -> Vec<&Artist>;
    pub fn items(&self) -> Vec<(&str, &[Artist])>;
    pub fn dump(&self) -> serde_json::Value;
}

// Filesystem sanitization
pub fn sanitize_dirname(max_filename_bytes: usize, name: &str, enforce_maxlen: bool, sanitize_diacritics: bool) -> String;
pub fn sanitize_filename(max_filename_bytes: usize, name: &str, enforce_maxlen: bool, sanitize_diacritics: bool) -> String;

// Hashing
pub fn sha256_struct(value: &impl Serialize) -> String;

// Collection helpers
pub fn flatten<T>(xxs: Vec<Vec<T>>) -> Vec<T>;
pub fn uniq<T: Eq + Hash + Clone>(xs: Vec<T>) -> Vec<T>;
```

### Design Decisions

- **`RoseError` modeled as a flat enum with `is_expected()` method** rather than separate error types or a trait hierarchy. This mirrors the Python `RoseExpectedError` subclass pattern while being idiomatic Rust. All four "does not exist" variants are expected; `Internal` is not.
- **`LazyLock` from `std::sync`** used instead of `once_cell::sync::Lazy` since Rust 1.80+ (we're on 1.91) has it stabilized in std. Avoids an extra dependency.
- **`serde_json` added as a dependency** for `sha256_struct` (canonical JSON serialization) and `ArtistMapping::dump()`. This is a lightweight, widely-used crate.
- **`sanitize_dirname`/`sanitize_filename` take `max_filename_bytes: usize` directly** instead of a Config reference, decoupling these utilities from the config module (which doesn't exist yet). The Python versions take a `Config` object but only use `c.max_filename_bytes`.
- **`Artist::new()` convenience constructor** added (not in Python) to reduce boilerplate in tests and call sites; alias defaults to `false`.
- **`ArtistMapping::dump()` returns `serde_json::Value`** — the Rust equivalent of `dataclasses.asdict()` returning a dict. The `Serialize` derive on `ArtistMapping` also allows direct serialization to any serde format.
- **`split_extension` treats extensions >6 bytes as stem** matching the Python behavior exactly (`len(ext.encode()) > 6`). The dot counts toward the 6-byte limit since `ext` includes the dot, matching Python's `os.path.splitext` behavior where ext includes the dot.

### Deviations from Plan

- **`split_extension` uses byte-length check `ext.len() > 6`** — Rust `str::len()` returns bytes, which matches Python's `len(ext.encode()) > 6`. No deviation in behavior.
- **`initialize_logging` not ported** — the Python module has logging setup code, but the task spec doesn't mention it and Rust uses `tracing` instead. Logging initialization will be handled separately.

### Known Issues / Tech Debt

- **`sha256_struct` uses JSON serialization** which may differ from the Python recursive `_rec_sha256_dataclass` approach in edge cases (e.g., key ordering in nested dicts). For the types currently used (Artist, ArtistMapping), this is not an issue since serde_json serializes struct fields in declaration order deterministically. If cross-language hash compatibility is ever needed, this should be revisited.
- **`VERSION` is duplicated** in `lib.rs` and `common.rs` — both are `"0.5.0"`. A future cleanup could have `lib.rs` re-export from `common` or use `env!("CARGO_PKG_VERSION")`.
