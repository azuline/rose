# Task 064: Tracks — Integration Tests (T-7.1)

## Objective
Add Rust integration tests for `run_actions_on_track` (end-to-end tag mutation) and `find_tracks_matching_rule` (rule matching via both optimized and FTS fallback paths).

## Context
The Rust tracks module has 8 structural unit tests that verify `Matcher` construction but never call the actual public functions. Python has 2 integration tests that exercise the full pipeline with real audio files and a seeded database. This task bridges the gap.

## Files to Read
- `rose-rs/rose-core/src/tracks.rs` — Rust implementation + tests (tests start ~line 159)
- `rose-py/rose/tracks_test.py` — Python tests: `test_run_action_on_track`, `test_find_matching_tracks`

## What to Implement

Add the following integration tests to `rose-rs/rose-core/src/tracks.rs` (requires seeded DB + audio fixtures):

1. **`test_run_actions_on_track_e2e`** — Get a track ID from the seeded database. Parse action `tracktitle/replace:Bop`. Call `run_actions_on_track`. Re-read the audio file tags. Assert `tracktitle == "Bop"`.

2. **`test_find_tracks_matching_rule_strict_artist`** — Parse matcher `artist:^Techno Man$`. Call `find_tracks_matching_rule`. Assert the correct set of track IDs is returned (all tracks by Techno Man).

3. **`test_find_tracks_matching_rule_strict_genre`** — Parse matcher `genre:^Deep House$`. Call `find_tracks_matching_rule`. Assert correct track IDs.

4. **`test_find_tracks_matching_rule_strict_label`** — Parse matcher `label:^Native State$`. Assert correct track IDs.

5. **`test_find_tracks_matching_rule_strict_descriptor`** — Parse matcher `descriptor:^Wet$`. Assert correct track IDs.

6. **`test_find_tracks_matching_rule_substring_fallback`** — Parse matcher `tracktitle:Track` (non-strict, uses FTS fallback). Call `find_tracks_matching_rule`. Assert correct track IDs returned.

7. **`test_run_actions_on_nonexistent_track_e2e`** — Call `run_actions_on_track` with a bogus track ID. Assert a `TrackDoesNotExist` (or equivalent) error is returned.
