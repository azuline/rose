# Task 030: VFS File Read Operations and Inode Management (M-11.4)

## Objective
Implement the `VirtualFS` struct that wraps `RoseLogicalCore` with the `fuser::Filesystem` trait, handling inode management, file handle translation, getattr/lookup caching, and FUSE-level read operations. Also implement 12 no-op FUSE stubs required for tool compatibility.

## Context
Rose is a music library manager being migrated from Python to Rust. The `VirtualFS` is the top-level FUSE struct that translates low-level FUSE callbacks (inode-based) into `RoseLogicalCore` calls (VirtualPath-based). It manages inode↔path mappings via `INodeMapper`, maintains short-lived caches for getattr/lookup performance (readdir triggers batch population), and handles the translation between `fuser` callbacks and Rose's logical operations.

## Constraints Relevant to This Task
- **Key Behavior #6:** `update_release_on_fh_close` — when a writable file handle is released, trigger `update_cache_for_releases` for that release. This is how the VFS refreshes after external tools modify files in-place.
- The `fuser::Filesystem` trait has specific method signatures. Use `fuser` (not `llfuse`).
- getattr/lookup caches are 1-second TTL, populated during readdir for batch performance (sequential getattr after ls is slow without caching).
- `readdir_cache` stores opendir results so subsequent readdir calls with offsets don't re-query.
- Ghost file/directory checks must happen BEFORE VirtualPath parsing in getattr/lookup.
- Entry attributes need `generation` (random int) and `entry_timeout` (30 seconds).

## What to Implement

### 1. `VirtualFS` struct
```rust
pub struct VirtualFS {
    fhandler: FileHandleManager,
    rose: RoseLogicalCore,
    inodes: INodeMapper,
    generation: u64,                    // random, fixed per mount
    getattr_cache: Arc<RwLock<TTLCache<u64, FileAttr>>>,   // 1s TTL
    lookup_cache: Arc<RwLock<TTLCache<(u64, Vec<u8>), FileAttr>>>,  // 1s TTL
    readdir_cache: Arc<RwLock<HashMap<u64, Vec<ReaddirEntry>>>>,
    ghost_existing_files: Arc<RwLock<TTLCache<String, bool>>>,       // 5s TTL
    in_progress_collage_additions: Arc<RwLock<TTLCache<String, bool>>>,  // 5s TTL
}
```

### 2. `impl fuser::Filesystem for VirtualFS`

#### Read operations:
- **`getattr(req, ino, reply)`**: Check getattr_cache first. Get path from INodeMapper. Check ghost files/collage additions. Parse VirtualPath. Call `rose.getattr()`. Set `st_ino`. Reply with FileAttr.
- **`lookup(req, parent, name, reply)`**: Check lookup_cache. Get path from INodeMapper. Check ghost files/collage additions. Parse VirtualPath. Call `rose.getattr()`. Set `st_ino`. Reply.
- **`opendir(req, ino, flags, reply)`**: Get path. Check collage additions (return empty dir). Parse VirtualPath. Call `rose.readdir()`. Store results in `readdir_cache` keyed by new FH. Reply with FH.
- **`readdir(req, ino, fh, offset, reply)`**: Read from `readdir_cache[fh]`. Populate getattr_cache and lookup_cache for each entry. Reply with entries starting at offset.
- **`releasedir(req, ino, fh, flags, reply)`**: Remove from readdir_cache.
- **`open(req, ino, flags, reply)`**: Get path. Handle in_progress_collage_additions (route to dev_null except for `.rose.{uuid}.toml`). Handle `._*` files on macOS (route to dev_null). Parse VirtualPath. Call `rose.open()`. Set ghost file if O_CREAT. Reply with FH.
- **`read(req, ino, fh, offset, size, flags, lock, reply)`**: Check dev_null sentinel (return empty). Call `rose.read()`. Reply with data.
- **`write(req, ino, fh, offset, data, write_flags, flags, lock, reply)`**: Check dev_null sentinel (return data.len()). Call `rose.write()`. Reply with bytes written.
- **`release(req, ino, fh, flags, lock, flush, reply)`**: Check dev_null. Call `rose.release()`. Reply ok.
- **`create(req, parent, name, mode, umask, flags, reply)`**: Resolve path, calc inode, delegate to open logic. Set ghost file. Reply with entry + FH.

#### Mutation operations (delegating to RoseLogicalCore):
- **`unlink(req, parent, name, reply)`**: Resolve, parse, call `rose.unlink()`. Reset caches. Remove inode.
- **`mkdir(req, parent, name, mode, umask, reply)`**: Handle collage addition (set in_progress_collage_additions, return ghost dir). Otherwise call `rose.mkdir()`. Reply with entry.
- **`rmdir(req, parent, name, reply)`**: Resolve, parse, call `rose.rmdir()`. Reset caches. Remove inode. Clean up collage additions.
- **`rename(req, parent, name, newparent, newname, flags, reply)`**: Resolve both paths, parse, call `rose.rename()`. Reset caches. Update inode mapping.

### 3. Cache management
- `reset_getattr_caches()`: Replace both getattr_cache and lookup_cache with fresh empty TTLCache instances.
- Called after any mutation (unlink, mkdir, rmdir, rename, create).

### 4. No-op FUSE stubs (12 stubs for tool compatibility)
Implement these as no-ops or minimal responses:
- `forget(req, ino, nlookup)` — reset getattr caches
- `mknod(req, parent, name, mode, umask, rdev, reply)` — return fake file entry
- `flush(req, ino, fh, lock_owner, reply)` — reply ok
- `setattr(req, ino, ...)` — call getattr and return its result
- `getxattr(req, ino, name, size, reply)` — reply error ENOATTR/ENODATA
- `setxattr(req, ino, name, value, flags, position, reply)` — reply ok (no-op)
- `listxattr(req, ino, size, reply)` — reply with empty xattr list
- `removexattr(req, ino, name, reply)` — reply error ENOATTR/ENODATA
- `statfs(req, ino, reply)` — return StatfsData with reasonable defaults (4KB blocks, 16GB virtual size, 255 name max)
- `ftruncate` / `fallocate` — handled via `setattr` or no-op
- `access(req, ino, mask, reply)` — reply ok
- `fsync(req, ino, fh, datasync, reply)` — reply ok

### 5. `mount_virtualfs(c: &Config, debug: bool)` and `unmount_virtualfs(c: &Config)`
- Mount using `fuser::mount2()` with options: `fsname=rose`, configurable workers from `c.max_proc`.
- On macOS: add `noappledouble` and `nolocalcaches` options.
- `unmount_virtualfs`: call `umount` subprocess on mount_dir.
