## Objective

## Context
Rose is a music library manager being migrated from Python to Rust. Path templates control how release directories and track files are named in both the source directory and the virtual filesystem. Templates use a Jinja-like syntax and are user-configurable.

  - Python method calls like `.rjust()` don't work in minijinja.
  - Verify `or` coalescing works for empty strings / custom types.
- Default templates must be updated to use the new filter syntax.

### Custom filters for minijinja
Register these as custom filters on the minijinja `Environment`:

- **`arrayfmt`**: Format `["a", "b", "c"]` as `"a, b & c"`. Single item -> just the item. Empty -> `""`.
- **`artistsarrayfmt`**: Format `Vec<Artist>` — exclude aliases, if <=3 show `"A, B & C"`, if >3 show `"A et al."`.
- **`artistsfmt`**: Format `ArtistMapping` with role decorations:
  - DJ: `"{dj} pres. {main}"`
  - Composer (if no DJ): `"{composer} performed by {main}"`
  - Conductor: `"{main} under {conductor}"`
  - Guest: `"{main} (feat. {guest})"`
  - Producer: `"{main} (prod. {producer})"`
  - Empty -> `"Unknown Artists"`.
  - Accepts an optional `omit` parameter (list of role names to skip).
- **`releasetypefmt`**: Map lowercase release type to display form (`"album"` -> `"Album"`, `"ep"` -> `"EP"`, `"djmix"` -> `"DJ-Mix"`, etc.).
- **`sortorder`**: `"First Last"` -> `"Last, First"`.
- **`lastname`**: `"First Last"` -> `"Last"`.
- **`pad(width)`**: Left-pad with `'0'` to `width` characters. Replaces `.rjust(2, '0')`.
- **`truncate(length)`**: Take first `length` characters. Replaces `[:10]` slicing.

### 2. Design Decisions

- **Temporary Release/Track structs:** Since the cache module doesn't exist yet, lightweight `Release` and `Track` structs are defined directly in `templates.rs`. These mirror the fields the Python `Release`/`Track` dataclasses expose to templates. When the cache module is implemented, these can be replaced or aliased.
- **Value conversion:** Artist, ArtistMapping, and RoseDate types are converted to minijinja `Value` via `BTreeMap`-based construction rather than implementing `minijinja::value::Object`. This avoids coupling the core types to the template engine and keeps the conversion explicit.
- **Shared Environment:** A `LazyLock<Environment<'static>>` holds the singleton minijinja environment with all filters registered. Templates are compiled on-demand via `Environment::template_from_str()`.
- **`get_sample_music` signature:** Changed from Python's `get_sample_music(config)` to `get_sample_music(music_source_dir: &Path)` since only the music directory path is needed from config. Returns a fixed-size array `[(Release, Track); 3]` instead of a tuple-of-tuples.

### 3. Custom Filter Implementations & Minijinja Quirks

- **`artistsfmt` with kwargs:** Uses `minijinja::value::Kwargs` for the optional `omit` parameter. When called as `{{ x | artistsfmt }}` (no kwargs), minijinja automatically provides an empty Kwargs. When called as `{{ x | artistsfmt(omit=["composer"]) }}`, the Kwargs is populated.
- **`or` coalescing:** Minijinja's `or` operator works for `None`/undefined values out of the box. `{{ originaldate or releasedate or '0000-00-00' }}` correctly falls through to the string literal when both dates are `None` (mapped to `Value::from(())`).
- **RoseDate as Value:** Dates are represented as `BTreeMap` values with a `year` key. The `{{ releasedate.year }}` syntax works via minijinja's attribute access on maps.
- **`map` filter:** Minijinja's built-in `map(attribute='name')` and `map('sortorder')` (applying a registered filter) work without custom code, enabling the classical template test to pass.

### 4. Deviations from Plan

- **No lazy compilation caching on PathTemplate:** Python used `@cached_property` to cache the compiled Jinja2 template on the `PathTemplate` instance. In Rust, `Environment::template_from_str()` is cheap enough that caching isn't needed at this stage. If profiling shows this is a bottleneck, a `OnceCell` can be added.
- **`RoseError::InvalidPathTemplate` variant added:** A new error variant `InvalidPathTemplate { key: String, message: String }` was added to `RoseError` in `common.rs` to support template compilation errors. This is marked as an expected (user-facing) error.
- **`PathContext` not yet wired into rendering:** The `context` parameter is accepted but currently unused (`let _ = context`). It will be wired in when the VFS views are implemented.

### 5. Known Issues / Tech Debt

- **Temporary Release/Track types:** These will need to be replaced or unified with the real cache module types. The template variable construction functions (`calc_release_variables`, `calc_track_variables`) will need updating at that point.
- **No `__str__` on RoseDate values:** When `{{ originaldate or releasedate }}` resolves to a RoseDate value, it renders as a map representation rather than the formatted date string. This works correctly for the current default templates (which only access `.year`), but if a user writes `{{ releasedate }}` directly, they'll get the map representation. This can be fixed later by implementing `minijinja::value::Object` for RoseDate.
- **PathContext fields not passed to templates:** Context fields (genre, artist, label, etc.) are not yet injected into the template rendering context. This will be implemented when VFS views are added.
