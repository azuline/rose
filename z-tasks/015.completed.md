# Task 015: Cache Update — Mtime Comparison and Change Detection (M-7.1b)

## Objective
Implement stage 2 of the cache update pipeline: compare directory and file mtimes against cached values, identify which releases and tracks have changed and need re-reading.

## Context
Rose is a music library manager being migrated from Python to Rust. The cache update pipeline minimizes disk I/O by only re-reading files whose mtime has changed. This task takes the scanned releases from stage 1 (task 014) and filters/annotates them with change information.

**Pipeline overview:**
1. Task 014: Scan directories → `Vec<ScannedRelease>`
2. **This task (015):** Compare mtimes → enrich with cached data, identify changes → `Vec<CacheCandidate>`
3. Task 016: Read tags from changed files → `Vec<PreparedRelease>`
4. Task 017: Rename directories
5. Task 018: Batch SQL writes

## Constraints Relevant to This Task
- Mtime is stored as a string representation of the float/timestamp (matching Python's `str(os.stat(f).st_mtime)`).
- Performance critical: the whole point is to avoid reading audio tags for unchanged files.
- `force=true` bypasses mtime comparison and marks everything as changed.
- SQLite PRAGMAs on every connection.

### Functions

1. **`detect_changes(config, scanned: Vec<ScannedRelease>, force: bool) -> Result<Vec<CacheCandidate>>`**

   Steps:
   a. Collect all release_ids from scanned releases.
   b. Batch query `releases_view` for all known IDs → `HashMap<String, (Release, HashMap<String, Track>)>`.
   c. Also batch query `tracks_view` for those release_ids.
   d. For each `ScannedRelease`:
      - Look up cached release. If not found → `release_dirty = true`, create default Release.
      - If `source_path` changed from cached → `release_dirty = true`.
      - Compare `datafile_mtime`:
        - If changed (or force): read sidecar TOML, parse `StoredDataFile`, update new/favorite/rating/added_at.
        - If sidecar data differs from parsed: rewrite sidecar (with lock). Mark dirty.
      - Detect cover art: scan files for `config.valid_cover_arts` matches. If cover changed → dirty.
      - For each audio file in `scanned.files`:
        - Get mtime. Compare to cached track mtime.
        - If same and not force → reuse cached track.
        - If different → mark `needs_read = true`.
      - Compute `unknown_cached_tracks`: cached track paths not found in current file listing.

2. **Helper: `batch_fetch_cached(config, release_ids) -> Result<HashMap<String, (Release, HashMap<String, Track>)>>`** — two SQL queries, returns map of release_id → (Release, {source_path → Track}).

### Data flow to next stage
`Vec<CacheCandidate>` is passed to task 016. Each entry contains which tracks need tag reading (`needs_read=true`) and which can be reused from cache.

### Key decisions

- **`CachedReleaseMap` type alias**: Added to satisfy clippy's `type_complexity` lint on the complex nested `HashMap` return type.
- **`cached_release` always `Some`**: Even for unchanged releases, `cached_release` is always `Some`. For new releases (not in cache), a default `Release` with empty fields is created — matching the Python behavior where `release = Release(id=..., ...)`.
- **Cover art detection**: Uses `config.valid_cover_arts()` (cross product of stems × extensions) with case-insensitive filename matching, taking the first match. This matches the Python logic at line 718–724.
- **Sidecar rewrite with lock**: When `StoredDataFile::serialize()` produces data different from what's on disk (schema upgrade), the sidecar is rewritten under an advisory lock (`release-{uuid}`) matching Python's `release_lock_name`.
- **Track mtime comparison**: For each audio file, the on-disk mtime string is compared against the cached track's `source_mtime`. Unchanged tracks are reused (with `needs_read=false` and `cached=Some(track)`), changed tracks need re-reading (`needs_read=true`).
- **`unknown_cached_tracks`**: After processing all on-disk files, remaining entries in the cached tracks map are collected as `unknown_cached_tracks` — these are tracks that were in the cache but no longer exist on disk.

### Data flow to task 016

The `Vec<CacheCandidate>` output provides everything task 016 needs for tag reading:
- `tracks[i].needs_read` — if true, read audio tags from `tracks[i].path`
- `tracks[i].cached` — if `needs_read=false`, reuse this `Track` as-is
- `release_dirty` — whether the release row needs updating in the DB
- `stored_data` — new/favorite/rating/added_at from the sidecar
- `cover_image_path` — detected cover art, or None
- `unknown_cached_tracks` — track source_paths to delete from the DB
- `cached_release` — previous release data for comparison/reference
