# Task 042: Port CLI Config/Misc Commands (M-12.11)

## Objective
Wire the config-related CLI subcommands (`rose config generate-completion` and `rose config preview-templates`) to their implementations.

## Context
Rose is a music library manager being migrated from Python to Rust. The config subcommand group provides shell completion generation (built into clap) and a template preview tool that renders sample data through the configured path templates.

## Constraints Relevant to This Task
- Shell completion generation is a built-in clap feature via `clap_complete`. Supported shells: bash, zsh, fish (and optionally elvish, powershell).
- Template preview uses `get_sample_music()` and `evaluate_release_template()` / `evaluate_track_template()` from rose-core to render 3 sample releases and tracks through each configured template.

## What to Implement

### Subcommands under `rose config`:

#### `rose config generate-completion <SHELL>`
Generate a shell completion script to stdout.

Arguments:
- `SHELL` (required) — one of: `bash`, `zsh`, `fish`

Implementation using clap_complete:
```rust
use clap::CommandFactory;
use clap_complete::{generate, Shell};

fn generate_completion(shell: Shell) {
    let mut cmd = Cli::command();
    generate(shell, &mut cmd, "rose", &mut std::io::stdout());
}
```

Add `clap_complete` as a dependency of `rose-cli`.

#### `rose config preview-templates`
Preview the configured path templates with sample music data.

Implementation — port `preview_path_templates` from `templates.py`:
1. Load config.
2. Call `get_sample_music(&config)` to get 3 (release, track) sample pairs.
3. For each template category (source, releases, releases_new, releases_added_on, releases_released_on, artists, genres, descriptors, labels, collages):
   - Print the label (dimmed, underlined).
   - Evaluate the release template with each of the 3 samples (position "1", "2", "3").
   - Evaluate the track template with each of the 3 samples.
4. For playlists: only print the track template (playlists don't have release-level paths).

Output formatting: use terminal styling if available, or plain text with clear labels.
