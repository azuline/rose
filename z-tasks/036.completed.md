# Task 036: Port CLI Track Commands (M-12.5)

## Objective
Wire all track-related CLI subcommands to rose-core functions, including track argument resolution (UUID or path).

## Context
Rose is a music library manager being migrated from Python to Rust. Track commands let users print track info as JSON and run rule actions on individual tracks. Track arguments accept either a UUID or a filesystem path to an audio file.

## Constraints Relevant to This Task
- Track argument resolution: if the argument is a valid UUID, use it directly. Otherwise, open the audio file with `AudioTags::from_file()`, read the `id` tag. Error if not found.
- `run-rule` `--yes` inverts to `confirm_yes=false`.

## What to Implement

### Helper: `parse_track_argument(t: &str) -> Result<String>`
1. If `t` is a valid UUID, return it.
2. Otherwise, treat as file path, call `AudioTags::from_file(path)`, extract `.id`.
3. Error with helpful message listing the 3 accepted formats (UUID, source path, VFS path).

### Subcommands (all under `rose tracks`):

#### `rose tracks print <TRACK>`
Print a single track as JSON (includes release info). Calls `dump_track(c, id)`.

#### `rose tracks print-all [MATCHER]`
Print all tracks as JSON. Optional matcher (parsed via `Matcher::parse`). Calls `dump_all_tracks(c, matcher)`.

#### `rose tracks run-rule <TRACK> [ACTIONS...] [--dry-run] [--yes]`
Run rule actions on a single track. Parses each action via `Action::parse`. `--yes` bypasses confirmation.

## API to Produce

fn parse_track_argument(t: &str) -> Result<String>;
