# Task 062: Releases — Editor Flow Integration Tests (T-6.2)

## Objective
Add Rust integration tests for the `edit_release` flow: the full edit round-trip with per-field dirty checking, and the failure + resume file workflow.

## Context
Python's `test_edit_release` is one of the most comprehensive integration tests in the codebase — it modifies 15+ fields (title, releasetype, dates, artists, genres, descriptors, labels, track titles, track artists) via the editor interface and verifies every field roundtrips correctly. Python's `test_edit_release_failure_and_resume` tests the failure recovery path. Neither has a Rust equivalent.

## Files to Read
- `rose-rs/rose-core/src/releases.rs` — Rust implementation + tests
- `rose-py/rose/releases_test.py` — Python tests: `test_edit_release`, `test_edit_release_failure_and_resume`

## What to Implement

1. **Refactor `edit_release`** to accept an `editor_fn` callback (same pattern as Tasks 059/060) so tests can supply TOML transformations without spawning `$EDITOR`.

2. **`test_edit_release_full`** — Seed a release with known metadata. Call `edit_release` with a callback that modifies: releasetitle, releasetype, releasedate, originaldate, edition, catalognumber, labels, genres, secondary_genres, descriptors, releaseartists, and at least one track's title and artists. Assert every modified field is correct in both the cache DB and the audio file tags.

3. **`test_edit_release_no_changes`** — Call `edit_release` with a callback that returns the TOML unchanged. Assert no tags are flushed (no-op).

4. **`test_edit_release_failure_and_resume`** — Call `edit_release` with a callback that returns invalid TOML (e.g. bad releasetype). Assert a `ReleaseEditFailed` error with a resume file path. Verify the resume file exists on disk. Call `edit_release` again with `resume_file` pointing to the saved file, with a callback that fixes the error. Assert the edit succeeds and the resume file is deleted.

## Completed

### Changes Made

1. **Refactored `edit_release`** (`rose-rs/rose-core/src/releases.rs`):
   - Added `EditorFn<'a>` type alias: `Option<&'a dyn Fn(&str) -> Result<String, RoseError>>`
   - Added `editor_fn` parameter to `edit_release()` — when `Some`, the callback replaces `$EDITOR`; when `None`, existing behavior is preserved
   - Updated CLI call site in `rose-rs/rose-cli/src/main.rs` to pass `None`

2. **`test_edit_release_full`** — Seeds a release with 2 tracks via real `.m4a` files, calls `edit_release` with a callback that modifies: title, releasetype, releasedate, originaldate, edition, catalognumber, labels, genres, secondary_genres, descriptors, releaseartists, and one track's title + artists. Asserts all fields roundtrip correctly in both the cache DB and the on-disk audio tags.

3. **`test_edit_release_no_changes`** — Calls `edit_release` with an identity callback. Verifies the audio file was NOT re-written (mtime unchanged) and tags are identical.

4. **`test_edit_release_failure_and_resume`** — Calls `edit_release` with a callback injecting an unknown artist role (`bogus_role`). Asserts the error, verifies resume file exists on disk. Re-invokes with `resume_file` and a fixing callback. Asserts the edit succeeds, resume file is deleted, and the fix is applied.
