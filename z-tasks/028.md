# Task 028: VFS Path Parser and Name Generation (M-11.2)

## Objective
Implement the `VirtualPath` parser and `VirtualNameGenerator` for the Rose VFS, handling all 12 view types, path parsing/resolution, and template-based name generation with 2-hour TTL for media player compatibility.

## Context
Rose is a music library manager being migrated from Python to Rust. The VFS presents the music library as a virtual directory tree with 12 top-level views. The path parser converts raw filesystem paths into semantic `VirtualPath` structs. The `VirtualNameGenerator` creates virtual directory/file names from release/track metadata using templates, and maintains inverse mappings for resolving entity IDs from paths.

## Constraints Relevant to This Task
- **Key Behavior #5:** `VirtualNameGenerator` caches paths for 2 hours so media players with cached old paths can still read files after metadata changes. Old paths don't show in readdir but still resolve.
- **Key Behavior #12:** `Sanitizer` has a circular dependency with `RoseLogicalCore` — on cache miss, `unsanitize()` calls `readdir()` which calls `sanitize()`. Use `DashMap` for the sanitizer mappings to avoid deadlocks.
- The 12 view types are: Root, Releases, Artists, Genres, Descriptors, Labels, Loose Tracks, Collages, Playlists, New, Favorites, Added On, Released On.
- Path segments use numbered prefixes: `"1. Releases"`, `"2. Artists"`, etc.
- Blacklisted filenames (`.git`, `.DS_Store`, `.Trash`, `.Trash-1000`, `HEAD`, `.envrc`) return ENOENT immediately.

## What to Implement

### 1. `VirtualPath` (frozen/immutable struct)

```rust
    pub descriptor: Option<String>,
    pub label: Option<String>,
    pub collage: Option<String>,
    pub playlist: Option<String>,
    pub release: Option<String>,  // May be set to ALL_TRACKS ("!All Tracks")
    pub file: Option<String>,
}
```

### 2. `ViewType` enum
12 variants: `Root`, `Releases`, `Artists`, `Genres`, `Descriptors`, `Labels`, `LooseTracks`, `Collages`, `Playlists`, `New`, `Favorites`, `AddedOn`, `ReleasedOn`.

### 3. `VirtualPath::parse(path: &Path) -> Result<VirtualPath>`
- Split path into segments. Return `Root` for `/`.
- Blacklist check: if last segment is `.git`, `.DS_Store`, `.Trash`, `.Trash-1000`, `HEAD`, `.envrc` → return ENOENT.
- Match first segment against numbered prefixes:
  - `"1. Releases"` → Releases view (2 parts = view, 3 = release, 4 = file)
  - `"1. Releases - New"` → New view (same depth structure)
  - `"1. Releases - Favorites"` → Favorites view
  - `"1. Releases - Added On"` → Added On view
  - `"1. Releases - Released On"` → Released On view
  - `"2. Artists"` → Artists view (2=view, 3=artist, 4=release, 5=file)
  - `"3. Genres"` → Genres view (same depth as Artists)
  - `"4. Descriptors"` → Descriptors view
  - `"5. Labels"` → Labels view
  - `"6. Loose Tracks"` → Loose Tracks view (2=view, 3=release, 4=file)
  - `"7. Collages"` → Collages view (2=view, 3=collage, 4=release, 5=file)
  - `"8. Playlists"` → Playlists view (2=view, 3=playlist, 4=file — NO release level)
- Return ENOENT for excess depth or unrecognized prefixes.

### 4. `VirtualPath` helper methods
- `release_parent()` → parent VirtualPath for release name lookup
- `track_parent()` → parent VirtualPath for track name lookup
- `artist_parent()`, `genre_parent()`, etc. → parent for Sanitizer lookups

### 5. `VirtualNameGenerator`
- Two `TTLCache` maps (2-hour TTL): `(VirtualPath, String) → String` for release and track name→ID resolution.
- Template evaluation caches: `HashMap<CacheKey, String>` for computed names.
- `list_release_paths(parent, releases) -> Iterator<(Release, String)>`:
  - Select template based on view type. Evaluate via `evaluate_release_template()`.
  - Sanitize via `sanitize_dirname()`. Handle collisions by appending ` [N]`.
  - Collage releases get zero-padded position prefix.
  - Store in TTL cache for later lookup.
- `list_track_paths(parent, tracks) -> Iterator<(Track, String)>`:
  - Select template (track vs all_tracks) based on view type and whether release == ALL_TRACKS.
  - Evaluate via `evaluate_track_template()`. Sanitize via `sanitize_filename()`.
  - Handle collisions by inserting ` [N]` before file extension.
  - Playlist tracks get zero-padded position prefix.
  - Store in TTL cache.
- `lookup_release(p) -> Option<String>`: TTL cache lookup, bumps expiry.
- `lookup_track(p) -> Option<String>`: TTL cache lookup, bumps expiry.

### 6. `Sanitizer` (uses DashMap to avoid deadlock)
- Two `DashMap<String, String>` maps: `to_sanitized` and `to_unsanitized`.
- `sanitize(unsanitized) -> String`: cache miss calls `sanitize_dirname()`, stores both directions.
- `unsanitize(sanitized, parent) -> Result<String>`: cache miss triggers a `readdir()` on the parent to populate the cache, then retries. This is the circular dependency — use `DashMap` (not `RwLock`) to ensure readdir's `sanitize()` calls don't deadlock with the ongoing `unsanitize()`.

### 7. `CanShower`
- Whitelist/blacklist filtering for artists, genres, descriptors, labels.
- Constructed from `Config.vfs.{entity}_whitelist` / `{entity}_blacklist`.
- `artist(name) -> bool`, `genre(name) -> bool`, `descriptor(name) -> bool`, `label(name) -> bool`.
