# Task 046: Expose Write Operations to Python (M-14.3)

## Objective
Expose write/mutation operations from `rose-core` to Python via PyO3, completing the Python scripting API with tag editing, release/collage/playlist CRUD, and rule execution.

## Context
Rose is a music library manager being migrated from Python to Rust. The PyO3 crate `rose-rs/rose-py/` already exposes `Config` (task 044) and all read operations (task 045). This task adds the remaining write operations so Python scripts have full control over the library.

## Constraints Relevant to This Task
- Same patterns as prior tasks: `#[pyfunction]`, accept `&PyConfig`, convert errors to `PyErr`.
- `AudioTags` needs both read and write exposure (`from_file` and `flush`).
- Rule types (`Matcher`, `Pattern`, `Action`, `Rule`) should be exposed if rule execution is exposed, or the Python API can accept string representations parsed internally.
- Functions that interact with `$EDITOR` (like `edit_release`) may not be practical to expose — document this decision.

- All `list_*`, `get_*`, `update_cache` functions exposed.

## Completed

### Full list of exposed write functions

**AudioTags** (`#[pyclass(name = "AudioTags")]`):
- `from_file(path: str) -> AudioTags` — classmethod, reads tags from disk.
- `flush(config: Config)` — writes modified tags back to disk (uses `config.write_parent_genres`).
- Getters: `tracktitle`, `releasetitle`, `tracknumber`, `discnumber`, `duration_seconds`, `releasetype`, `releasedate`, `genres`, `secondary_genres`, `descriptors`, `labels`, `edition`, `catalognumber`, `path`.
- Setters: `tracktitle`, `releasetitle`, `tracknumber`, `discnumber`, `releasetype`, `genres`, `secondary_genres`, `descriptors`, `labels`, `edition`, `catalognumber`.

**Release write functions:**
- `toggle_release_new(config, release_id)`
- `toggle_release_favorite(config, release_id)`
- `set_release_rating(config, release_id, rating=None)` — rating is `Option<u8>`
- `delete_release(config, release_id)`
- `set_release_cover_art(config, release_id, path)`
- `delete_release_cover_art(config, release_id)`
- `create_single_release(config, track_path, releasetype=None)` — defaults to "single"

**Collage write functions:**
- `create_collage(config, name)`
- `rename_collage(config, old_name, new_name)`
- `delete_collage(config, name)`
- `add_release_to_collage(config, collage_name, release_id)`
- `remove_release_from_collage(config, collage_name, release_id)`

**Playlist write functions:**
- `create_playlist(config, name)`
- `rename_playlist(config, old_name, new_name)`
- `delete_playlist(config, name)`
- `add_track_to_playlist(config, playlist_name, track_id)`
- `remove_track_from_playlist(config, playlist_name, track_id)`
- `set_playlist_cover_art(config, playlist_name, path)`
- `delete_playlist_cover_art(config, playlist_name)`

**Rule execution:**
- `execute_stored_metadata_rules(config, dry_run=None, confirm_yes=None)` — runs all config rules, defaults to `dry_run=False, confirm_yes=True`.
- `execute_metadata_rule(config, matcher, actions, ignore=None, dry_run=None, confirm_yes=None)` — parses and executes a single rule from DSL strings.

### Operations intentionally omitted
- `edit_release` — requires spawning `$EDITOR` for interactive TOML editing, not practical for a Python API.
- `edit_collage`, `edit_playlist` — same reason; interactive editor protocol not useful from scripting.
- `filter_releases`, `filter_tracks` — complex multi-parameter filter functions; can be added later if needed.

### AudioTags setter strategy
- Mutable fields (`tracktitle`, `releasetitle`, `genres`, etc.) have both `#[getter]` and `#[setter]` methods that directly modify the inner `AudioTags` struct.
- `flush()` accepts `&PyConfig` and passes `config.write_parent_genres` to the inner `flush` call.
- Read-only fields (`duration_seconds`, `releasedate`, `path`) only have getters — `duration_seconds` and `path` aren't tag-writable, and `releasedate` requires `RoseDate` construction which isn't exposed.
