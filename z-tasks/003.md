# Task 003: Port genre_hierarchy.rs (M-1.3)

## Objective
Port the genre hierarchy data structures from Python to Rust, providing both child-to-parents and parent-to-transitive-children lookups.

## Context
Rose is a music library manager being migrated from Python to Rust. The genre hierarchy maps genres to their parent/child relationships (sourced from RateYourMusic). It's used during cache updates (genre expansion) and VFS filtering.

## Constraints Relevant to This Task
- The generator script (`scripts/rym-genres/generate.py`) already writes a JSON file for Rust consumption. Use `serde_json::from_str(include_str!(...))` to embed it at compile time.
- Data must be identical to the Python version.

## Files to Read
- **Python source:** `rose-py/rose/genre_hierarchy.py` (large file, ~5000+ lines of generated data) — understand the two maps: `TRANSITIVE_PARENT_GENRES` (child -> list of parents) and `TRANSITIVE_CHILD_GENRES` (parent -> list of children).
- **Generator:** `scripts/rym-genres/generate.py` — to understand what JSON is produced.

## What to Implement

### 1. Locate or generate the JSON data file
The generator script writes a JSON file for Rust. Find where it's placed (likely `rose-rs/src/genre_hierarchy.json` or `rose-rs/rose-core/src/genre_hierarchy.json`). If it doesn't exist yet, run the generator or create the JSON from the Python source.

The JSON should be a map of `genre_name -> [parent_genre_1, parent_genre_2, ...]` (the `TRANSITIVE_PARENT_GENRES` direction).

### 2. Create `rose-rs/rose-core/src/genre_hierarchy.rs`

**`GENRE_HIERARCHY`** (or `TRANSITIVE_PARENT_GENRES`): `HashMap<String, Vec<String>>` — maps a child genre to its transitive parent genres. Loaded from the JSON file at startup using `LazyLock` or `once_cell::sync::Lazy`.

**`TRANSITIVE_CHILD_GENRES`**: `HashMap<String, Vec<String>>` — the inverse map: parent genre to all transitive child genres. Computed at init time by inverting `GENRE_HIERARCHY`.

Use `include_str!` to embed the JSON at compile time, then deserialize with `serde_json::from_str` in a `LazyLock`/`Lazy` initializer.

### 3. Update `lib.rs`
Add `pub mod genre_hierarchy;`

## API to Produce
```rust
// rose-core/src/genre_hierarchy.rs
use std::collections::HashMap;

/// Child genre -> list of transitive parent genres.
pub static GENRE_HIERARCHY: LazyLock<HashMap<String, Vec<String>>>;

/// Parent genre -> list of transitive child genres (inverse of GENRE_HIERARCHY).
pub static TRANSITIVE_CHILD_GENRES: LazyLock<HashMap<String, Vec<String>>>;
```

## Tests to Write
1. **Non-empty:** `GENRE_HIERARCHY` is not empty (sanity check that JSON loaded).
2. **Known entry:** `GENRE_HIERARCHY["Acid House"]` contains `"House"` and `"Electronic Dance Music"`.
3. **Inverse correctness:** If `GENRE_HIERARCHY["X"]` contains `"Y"`, then `TRANSITIVE_CHILD_GENRES["Y"]` contains `"X"`.
4. **Inverse completeness:** Every genre that appears as a parent in `GENRE_HIERARCHY` has an entry in `TRANSITIVE_CHILD_GENRES`.
5. **No self-references:** No genre maps to itself in either direction.
