# Task 033: Port JSON Serialization / Dump Module (M-12.2)

## Objective
Port the `dump.py` module (288 lines) into Rust, providing JSON serialization for all Rose entities (releases, tracks, artists, genres, labels, descriptors, collages, playlists).

## Context
Rose is a music library manager being migrated from Python to Rust. The dump module converts cached entities to JSON for the `print` and `print-all` CLI commands. It lives as a module within the CLI crate (or optionally in `rose-core`) and calls `rose-core` query functions.

## Constraints Relevant to This Task
- JSON field names and structure must match the Python output for script compatibility. Use the existing `dump_test.ambr` syrupy snapshots as golden references.
- `dump_all_artists` has an N+1 query pattern (calls `find_releases_matching_rule` per artist). Reproduce this for now — optimize later.
- `_partition_releases_by_role` places a release into the FIRST matching role only (note the `break` in the Python loop).
- Use `serde_json` for serialization.

## What to Implement

### 1. Create `rose-rs/rose-cli/src/dump.rs` (or a dump module within rose-core)

#### `release_to_json(r: &Release) -> serde_json::Value`
Convert a Release to a JSON object. Include computed field `all_genres` = `uniq(genres + parent_genres + secondary_genres + parent_secondary_genres)`.

#### `track_to_json(t: &Track, with_release_info: bool) -> serde_json::Value`
Convert a Track to JSON. When `with_release_info=true`, flatten release fields into the track object.

#### Dump functions (each returns `Result<String>`):
- `dump_release(c, release_id) -> String` — single release with tracks
- `dump_all_releases(c, matcher: Option<Matcher>) -> String` — all/filtered releases with tracks
- `dump_track(c, track_id) -> String` — single track with release info
- `dump_all_tracks(c, matcher: Option<Matcher>) -> String` — all/filtered tracks
- `dump_artist(c, name) -> String` — artist with roles partitioned
- `dump_all_artists(c) -> String` — all artists (N+1 query, reproduce Python behavior)
- `dump_genre(c, name) -> String` — genre with releases
- `dump_all_genres(c) -> String` — all genres with releases
- `dump_label(c, name) -> String` — label with releases
- `dump_all_labels(c) -> String` — all labels with releases
- `dump_descriptor(c, name) -> String` — descriptor with releases
- `dump_all_descriptors(c) -> String` — all descriptors with releases
- `dump_collage(c, name) -> String` — collage with positioned releases
- `dump_all_collages(c) -> String` — all collages
- `dump_playlist(c, name) -> String` — playlist with positioned tracks and cover_image_path
- `dump_all_playlists(c) -> String` — all playlists

#### `_partition_releases_by_role(artist: &str, releases: &[Release]) -> HashMap<String, Vec<&Release>>`
Partition releases into role buckets (main, guest, remixer, producer, composer, conductor, djmixer). Each release goes into the FIRST matching role only.
