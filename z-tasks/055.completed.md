# Task 055: Audiotags — Preservation and Error Handling Tests (T-1.3)

## Objective
Add Rust tests for MP3 TXXX frame preservation, Vorbis vendor string preservation, corrupted file handling, and the raw `\\PARENTS:\\` genre encoding verification.

## Context
These are lower-severity gaps but cover important correctness properties: that third-party metadata survives a flush, that Vorbis vendor strings are preserved, that corrupted files produce clean errors, and that the genre parent encoding is byte-level correct.

## Files to Read
- `rose-rs/rose-core/src/audiotags.rs` — Rust implementation + tests
- `rose-py/rose/audiotags_test.py` — Python `test_write_parent_genres` (checks raw tag content)

## What to Implement

Add the following tests to `rose-rs/rose-core/src/audiotags.rs`:

1. **`mp3_txxx_preservation`** — Open an MP3 file, add a custom TXXX frame with a non-Rose description (e.g. `TXXX:REPLAYGAIN_TRACK_GAIN`), flush AudioTags (modifying some Rose field), re-read the raw file, assert the custom TXXX frame survives.

2. **`vorbis_vendor_string_preservation`** — Open a FLAC file, record the vendor string, flush AudioTags, re-read, assert the vendor string is unchanged.

3. **`corrupted_file_returns_error`** — Create a temp file with garbage bytes and a `.flac` extension, attempt `AudioTags::from_file`, assert it returns an error (not a panic).

4. **`genre_parent_raw_encoding`** — Enable `write_parent_genres` in config, flush a FLAC file with genres `["Deep House"]`, then read the raw Vorbis comment tag value (not via AudioTags) and assert it contains `\\PARENTS:\\` followed by the parent genres.

4 new test functions as listed above.
