# Task 027: Create rose-vfs Crate and Inventory Shared State (M-11.1)

## Objective
Create the `rose-vfs` binary crate at `rose-rs/rose-vfs/` and define all shared mutable state structures needed for the FUSE virtual filesystem, with correct thread-safe synchronization primitives.

## Context
Rose is a music library manager being migrated from Python to Rust. The VFS is a FUSE filesystem that presents the music library as a virtual directory tree. Python used the GIL for thread safety; Rust must use explicit synchronization. This task creates the crate scaffold and defines the 7 shared mutable state structures that all subsequent VFS tasks depend on.

## Constraints Relevant to This Task
- This is a NEW BINARY CRATE (`rose-rs/rose-vfs/`), not part of `rose-core`.
- Python's GIL protected all shared state. Rust must use `Arc<RwLock<T>>` or `DashMap` explicitly.
- **FIX BUG:** `FileHandleManager` counter wrapping: Python uses `self._state + 1 % 10_000` (operator precedence bug — `1 % 10_000 == 1`, so it just increments forever). Rust must use `(self._state + 1) % 10_000` with `max(10, ...)` to avoid reserved handles 0-9.
- Dependencies: `fuser` (not `llfuse`), `dashmap`, `rose-core` (path dependency).
- The `fuser` crate uses a different API from `llfuse` — it expects a struct implementing the `Filesystem` trait with methods receiving `&mut self` or `&self`.

## Prior Work
All `rose-core` library modules exist (common, audiotags, rule_parser, templates, config, cache, rules, releases, tracks, collages, playlists). The VFS will depend on these as a library.

### 2. `TTLCache<K, V>` (generic time-to-live cache)
- `HashMap<K, (V, Instant)>` backing store.
- Configurable TTL in seconds.
- Methods: `get(&self, key) -> Option<&V>`, `insert(&mut self, key, value)`, `remove(&mut self, key)`, `contains(&self, key) -> bool`.
- On `get`, refresh the TTL (update timestamp) — matches Python behavior at `virtualfs.py:152`.
- No automatic eviction (matches Python — "we will probably implement freeing entries later").

### 3. `FileHandleManager`
- Counter starting at 10. Reserved handle 9 = `/dev/null` sentinel.
- `next() -> u64`: returns `max(10, (self.state + 1) % 10_000)`. **This fixes the Python precedence bug.**
- `wrap_host(host_fh: i32) -> u64`: generates a rose FH, stores mapping.
- `unwrap_host(rose_fh: u64) -> Result<i32>`: looks up host FH, returns EBADF on miss.
- `dev_null: u64` constant (9).
- Internal: `HashMap<u64, i32>` for rose→host mapping.

### 4. `INodeMapper`
- Bidirectional map: `inode ↔ PathBuf`.
- Root inode = `fuser::FUSE_ROOT_ID` (1).
- Counter for next inode, incrementing (no wrapping — inodes grow to infinity, matching Python `virtualfs.py:1582-1585`).
- Methods: `get_path(inode, name: Option<&OsStr>) -> Result<PathBuf>`, `calc_inode(path) -> u64`, `remove_path(path)`, `rename_path(old, new)`.

### 5. Shared state inventory — define all 7 items with sync primitives

| State | Type | Sync Primitive | Purpose |
|-------|------|---------------|---------|
| `ghost_existing_files` | `TTLCache<String, bool>` | `Arc<RwLock<_>>` | Pretend files exist for 5s after creation |
| `in_progress_collage_additions` | `TTLCache<String, bool>` | `Arc<RwLock<_>>` | Ghost dirs for 5s during collage add |
| `getattr_cache` | `TTLCache<u64, EntryAttrs>` | `Arc<RwLock<_>>` | 1s cache for getattr after readdir |
| `lookup_cache` | `TTLCache<(u64, Vec<u8>), EntryAttrs>` | `Arc<RwLock<_>>` | 1s cache for lookup after readdir |
| `file_creation_special_ops` | `HashMap<u64, SpecialOp>` | `Arc<RwLock<_>>` | State machine for add-to-playlist / new-cover-art |
| `update_release_on_fh_close` | `HashMap<u64, String>` | `Arc<RwLock<_>>` | FH→release_id for cache refresh on close |
| `readdir_cache` | `HashMap<u64, Vec<ReaddirEntry>>` | `Arc<RwLock<_>>` | Stores opendir results for subsequent readdir calls |

### 6. `EntryAttrs` struct
