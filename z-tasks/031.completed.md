# Task 031: VFS Write Operations and Ghost File Protocol (M-11.5)

## Objective
Implement the ghost file protocol for adding releases to collages and tracks to playlists via the VFS, and the `file_creation_special_ops` state machine that spans multiple FUSE syscalls.

## Context
Rose is a music library manager being migrated from Python to Rust. The VFS supports adding releases to collages by `cp -r release_dir collage_dir/` and tracks to playlists by `cp track.flac playlist_dir/`. These operations span multiple FUSE syscalls and require ghost files/directories that pretend to exist temporarily so tools like `cp` don't error out.

## Constraints Relevant to This Task
- **Key Behavior #4:** Ghost file protocol. Adding a release to a collage via `mkdir` triggers a 6-step protocol spanning `mkdir`, `opendir`, `getattr`, `lookup`, `open`, with a 5s TTL ghost directory. Adding a track to a playlist has a 2s ghost file.
- Ghost files/directories must be checked BEFORE VirtualPath parsing in getattr/lookup/open.
- The `file_creation_special_ops` state machine must persist state across open→write→release syscalls.
- `cp -r` into a collage fires: mkdir (release dir) → opendir → readdir (returns empty) → for each file: create/open → write → release. The `.rose.{uuid}.toml` open triggers the actual `add_release_to_collage`.
- `cp` into a playlist fires: create/open → write (audio bytes) → release. On release, bytes are written to temp file, parsed with `AudioTags::from_file()` to extract track ID, then `add_track_to_playlist()`.

## What to Implement

### 1. Collage Ghost Directory Protocol (6 steps, 5s TTL)

**Step 1 — `mkdir` (VirtualFS level):**
When `mkdir` is called on a path like `/7. Collages/{collage_name}/{release_dirname}`:
- Parse VirtualPath. If `collage` is set and `release` is set:
  - Record the full path in `in_progress_collage_additions` TTLCache (5s TTL).
  - Do NOT call `rose.mkdir()`. Just return a fake dir entry.

**Step 2 — `opendir` on ghost directory:**
When `opendir` is called on a path in `in_progress_collage_additions`:
- Return a FH pointing to an empty directory (just `.` and `..` entries in readdir_cache).

**Step 3 — `getattr` / `lookup` on ghost directory or children:**
- `getattr`: If path is in `in_progress_collage_additions`, return dir stat.
- `lookup`: If parent path is in `in_progress_collage_additions`, return ENOENT (but don't error fatally — the caller will retry with create).

**Step 4 — `open` inside ghost directory:**
When `open` is called on a file inside an `in_progress_collage_additions` directory:
- If the file is `.rose.{uuid}.toml` with O_CREAT: this is the trigger! Extract the UUID from filename, call `add_release_to_collage(config, collage_name, release_id)`. Return dev_null FH.
- Otherwise: set the file path as a ghost_existing_file, return dev_null FH (black hole).

**Step 5 — Reads/writes to dev_null:**
Already handled: dev_null returns empty bytes on read, returns data.len() on write.

**Step 6 — Ghost expiry:**
After 5 seconds, the TTLCache entries expire naturally. Subsequent getattr/lookup on the ghost paths will parse normally and return ENOENT.

**Cleanup in `rmdir`:**
Remove path from `in_progress_collage_additions` when rmdir is called on it.

### 2. Playlist Ghost File Protocol (3 steps, 5s TTL for ghost)

**Step 1 — `open`/`create` with O_CREAT for audio file in playlist:**
When opening a file with an audio extension in a playlist directory:
- Create a new FH via `fhandler.next()`.
- Store in `file_creation_special_ops` as `AddTrackToPlaylist { playlist, ext, data: Vec::new() }`.
- Set the file path as a ghost_existing_file.
- Return the FH.

**Step 2 — `write` to special op FH:**
When write is called with an FH in `file_creation_special_ops`:
- Append data to the stored `data` Vec at the given offset. Truncate bytes after offset first.
- Return `data.len()`.

**Step 3 — `release` of special op FH:**
When release is called with an FH in `file_creation_special_ops`:
- If operation is `AddTrackToPlaylist`:
  - Write accumulated bytes to a temp file with the correct extension.
  - Parse with `AudioTags::from_file(temp_path)` to extract `track_id`.
  - If track_id found: call `add_track_to_playlist(config, playlist, track_id)`.
  - If not found: log warning and return.
  - Clean up: delete temp file, remove from `file_creation_special_ops`.

### 3. Cover Art Creation Protocol (same pattern as playlist)

**Release cover art (`open` in release dir with O_CREAT and valid cover art filename):**
- Store in `file_creation_special_ops` as `NewCoverArt { entity: Release(id), ext, data: Vec::new() }`.
- On `release`: write bytes to temp file, call `set_release_cover_art(config, release_id, temp_path)`.

**Playlist cover art (`open` in playlist dir with O_CREAT and valid cover art filename):**
- Store as `NewCoverArt { entity: Playlist(name), ext, data: Vec::new() }`.
- On `release`: write bytes to temp file, call `set_playlist_cover_art(config, playlist_name, temp_path)`.

### 4. `read` for special ops
When `read` is called on a special op FH (rare but possible):
- Return bytes from the stored data buffer at the given offset/length.

### 5. `ftruncate` for special ops and dev_null
- dev_null: no-op.
- Special ops: could resize the stored data Vec. For simplicity, call `os::ftruncate` only on unwrapped host FHs.

### 6. MacOS `._*` file handling
When `open` is called on a file starting with `._` (extended attribute files on macOS):
- Set as ghost_existing_file, return dev_null. These are silently consumed.
