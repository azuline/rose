# Task 024: Port tracks.rs — Track Operations (M-9.2)

## Objective
Port the tracks module from Python (`tracks.py`, 67 lines) to Rust in `rose-rs/rose-core/src/tracks.rs`. This is a small module providing track-level rule matching and action execution.

## Context
Rose is a music library manager being migrated from Python to Rust. The tracks module is a thin wrapper that enables track-level filtering via the rules engine and action execution on individual tracks. It delegates most work to the rules module and cache filter queries.

## Constraints Relevant to This Task
- This is a small module (67 lines Python). Keep it focused.
- Optimized strict-match lookups should use `filter_tracks()` from cache directly.
- Fallback path uses FTS search + false positive filtering.

## What to Implement

### 1. `find_tracks_matching_rule(c, matcher) -> Vec<Track>`
Optimize strict-match lookups for common patterns:
- `matcher.tags == ALL_TAGS["artist"]` → `filter_tracks(c, all_artist_filter=needle)`
- `matcher.tags == ALL_TAGS["trackartist"]` → `filter_tracks(c, track_artist_filter=needle)`
- `matcher.tags == ALL_TAGS["releaseartist"]` → `filter_tracks(c, release_artist_filter=needle)`
- `matcher.tags == ["genre"]` → `filter_tracks(c, genre_filter=needle)`
- `matcher.tags == ["label"]` → `filter_tracks(c, label_filter=needle)`
- `matcher.tags == ["descriptor"]` → `filter_tracks(c, descriptor_filter=needle)`

Fallback: `fast_search_for_matching_tracks` → `list_tracks` → `filter_track_false_positives_using_read_cache`.

### 2. `run_actions_on_track(c, track_id, actions, dry_run, confirm_yes)`
- Look up track via `get_track(c, track_id)`. Error if not found.
- Read audio tags via `AudioTags::from_file(track.source_path)`.
- Delegate to `execute_metadata_actions(c, actions, vec![audiotag], dry_run, confirm_yes)`.

### 3. Error type
- `TrackDoesNotExistError` — raised when `track_id` is not found.

