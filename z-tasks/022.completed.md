# Task 022: Port rules.rs — Rules Engine (M-8.1)

## Objective
Port the rules engine from Python (`rules.py`, 898 lines) to Rust in `rose-rs/rose-core/src/rules.rs`. This implements the 5-phase pipeline for performant substring tag querying and bulk metadata updating.

## Context
Rose is a music library manager being migrated from Python to Rust. The rules engine is the core mechanism for bulk metadata queries and modifications — it uses FTS for fast searching, reads audio tags to filter false positives, applies actions in-memory, prompts for confirmation, then flushes changes to disk. Actions on `new`/`favorite`/`rating` write to `.rose.{uuid}.toml` sidecar files, not audio tags.

## Constraints Relevant to This Task
- Sed action regex uses Rust `regex` crate replacement syntax (`$1` not `\1` as in Python). Document this difference.
- Use `fancy-regex` only if lookaround is needed; prefer `regex` crate.
- Actions on `new`/`favorite`/`rating` modify `.rose.{uuid}.toml`, NOT audio tags. Writes are deduplicated per-release directory.
- **FIX BUG:** `--ignore` for `new`/`favorite` at Python `rules.py:302,306` incorrectly assigns to `match` instead of `skip`. Use `skip = ...` in Rust.

## What to Implement

### 1. `fast_search_for_matching_tracks(c, matcher) -> Vec<FastSearchResult>`
- Convert matcher pattern to FTS query using `_convert_matcher_to_fts_query` (NEAR-based, `¬`-separated characters).
- Strip artist role suffixes (e.g. `[main]`) from tag names for FTS columns.
- Execute FTS query joining `rules_engine_fts` → `tracks`.

### 2. `fast_search_for_matching_releases(c, matcher) -> Vec<FastSearchResult>`
- Same as tracks but joins through to `releases` table.
- Reject track-only tags unless both `trackartist` and `releaseartist` are present (shorthand).
- Support `include_loose_tracks` flag.

### 3. `filter_track_false_positives_using_tags(matcher, results, ignore) -> Vec<AudioTags>`
- Read actual audio tags for each result. Match against pattern per field.
- For `new`/`favorite`/`rating` fields, lazy-load the `.rose.{uuid}.toml` datafile.
- **BUG FIX:** In the ignore loop for `new`/`favorite`, assign to `skip`, not `match`. Python lines 302,306 incorrectly use `match = matches_pattern(...)` — Rust must use `skip = matches_pattern(...)`.

### 4. `filter_track_false_positives_using_read_cache(matcher, tracks) -> Vec<Track>`
- Match against cache fields (release.releasedate, release.genres, etc.) without disk reads.

### 5. `filter_release_false_positives_using_read_cache(matcher, releases) -> Vec<Release>`
- Release-level matching only; ignores track tags.

### 6. `execute_metadata_actions(c, actions, audiotags, dry_run, confirm_yes)`
- Phase 3: Deep-clone tags, apply actions in-memory, compute per-track diffs.
- Phase 4: Display changes, y/n confirmation for ≤25 tracks, enter-number for >25.
- Phase 5: Flush AudioTags and datafile changes. Deduplicate datafile writes per directory.
- Phase 6: Trigger `update_cache_for_releases` for changed releases.

### 7. Action execution helpers
- `matches_pattern(pattern, value) -> bool` — strict start/end/both/substring matching.
- `execute_single_action(action, value) -> Option<String>` — Replace, Sed, Delete.
- `execute_multi_value_action(action, values) -> Vec<String>` — Replace (semicolon split), Sed, Split, Add, Delete.
- `value_to_str(value) -> String` — bool→"true"/"false", RoseDate→string, None→"".

### 8. `execute_stored_metadata_rules(c, dry_run, confirm_yes)`
- Iterate over `c.stored_metadata_rules`, call `execute_metadata_rule` for each.

### What was implemented

5. **`filter_track_false_positives_using_read_cache(matcher, tracks)`** — Cache-based track filtering without disk reads. Checks all track and release fields.

6. **`filter_release_false_positives_using_read_cache(matcher, releases, include_loose_tracks)`** — Cache-based release filtering, release-level tags only.
