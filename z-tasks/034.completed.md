# Task 034: Port CLI Cache Commands (M-12.3)

## Objective
Wire the `rose cache update` CLI subcommand to the existing `rose-core` cache update function.

## Context
Rose is a music library manager being migrated from Python to Rust. The CLI is a thin wrapper over `rose-core`. This task implements the cache-related subcommand that was stubbed in task 032.

## Constraints Relevant to This Task
- Config is loaded lazily (only when the subcommand needs it).
- The `--force` flag forces re-reading all data from disk even for unchanged files.

## Prior Work
From tasks 001–031, rose-core provides:
- `Config::load(path: Option<&Path>) -> Result<Config>`
- `update_cache(c: &Config, force: bool) -> Result<()>`
- `maybe_invalidate_cache_database(c: &Config) -> Result<()>`

From task 032, the CLI crate exists at `rose-rs/rose-cli/` with clap command structure and stub subcommands.

## Files to Read
- `rose-cli/rose_cli/cli.py` lines 140–151 — Python cache update command
- `rose-rs/rose-cli/src/main.rs` — current CLI structure with stubs
- `rose-rs/rose-core/src/cache.rs` — `update_cache` function signature

## What to Implement

### Subcommand: `rose cache update [--force]`
```
rose cache update
rose cache update --force
rose cache update -f
```

Implementation:
1. Load config.
2. Call `maybe_invalidate_cache_database(&config)?`.
3. Call `update_cache(&config, force)?`.

Replace the stub for this subcommand in main.rs with the actual implementation.

## API to Produce
No new public API. This wires an existing stub to an existing function.

## Tests to Write
1. Verify `rose cache update --help` shows the `--force` flag.
2. Integration test (if feasible): run `rose cache update` against a test music directory and verify it completes without error.
