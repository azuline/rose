# Task 012: Cache Read Queries — Simple (M-6.3)

## Objective
Implement all simple cache read functions: `get_*`, `list_*`, `*_exists`, `get_*_of_*`, and `*_within_*` queries against the SQLite cache.

## Context
Rose is a music library manager being migrated from Python to Rust. The SQLite read cache stores releases, tracks, collages, and playlists. This task implements the simple (non-filtered) read queries that the rest of the system uses to fetch cached data.

## Constraints Relevant to This Task
- SQLite PRAGMAs (WAL, foreign_keys, busy_timeout=15s) on every connection.
- Artist alias resolution: when looking up artists, include all transitive aliases from `Config.artist_aliases_map`.
- Genre hierarchy: `genre_exists` checks transitive child genres via `TRANSITIVE_CHILD_GENRES`.

### Internal helpers added

- `TrackRowData` struct + `cached_track_row_from_view()` — intermediate track row extraction without release resolution, enabling batch release fetching.
- `assemble_track()` — combines a `TrackRowData` with its `Release` into a `Track`.
- `fetch_releases_by_ids()` — batch-fetches releases by a list of IDs into a `HashMap`, used by `list_tracks`, `get_playlist_tracks`, etc.

### Decisions and deviations

- **`&str` instead of `String`**: Rust functions take `&str` for ID/name parameters rather than owned `String`, which is more idiomatic.
- **`&[Release]` instead of `&[Release]` (owned)**: `get_tracks_of_releases` takes `&[Release]` and clones releases into results, matching Python semantics while being Rust-idiomatic.
- **No `bool | None` return for `track_within_release`**: Python returns `bool | None` but the None case only happens when the track doesn't exist. The Rust version returns `bool` (false if not found), matching the practical semantics.
- **Empty ID list short-circuit**: `list_releases` and `list_tracks` return empty `Vec` immediately when given an empty ID slice, avoiding invalid SQL.
- **`GENRE_HIERARCHY` used for parent genre accumulation**: Rust's `GENRE_HIERARCHY` (child→parents) is equivalent to Python's `TRANSITIVE_PARENT_GENRES`.
