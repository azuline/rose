# Task 056: Cache — Rename-Doesn't-Break-Relations Tests (T-2.1)

## Objective
Add Rust tests verifying that renaming a release directory does not break its membership in collages or playlists, and that playlist `description_meta` is regenerated when releases are updated.

## Context
Python has explicit tests (`test_update_cache_collages_on_release_rename`, `test_update_cache_playlists_on_release_rename`, `test_update_tracks_updates_playlists_description_meta`) that verify relational integrity across renames. The Rust cache test suite (~176 tests) doesn't have equivalents for these specific scenarios.

## Files to Read
- `rose-rs/rose-core/src/cache.rs` — Rust implementation + tests (tests start ~line 5191)
- `rose-py/rose/cache_test.py` — Python tests for reference

## What to Implement

Add the following tests to `rose-rs/rose-core/src/cache.rs`:

1. **`test_release_rename_preserves_collage_membership`** — Seed a release in a collage. Rename the release's source directory. Run cache update. Assert the release is still in the collage (not flagged missing).

2. **`test_release_rename_preserves_playlist_membership`** — Seed a release with tracks in a playlist. Rename the release's source directory. Run cache update. Assert the tracks are still in the playlist (not flagged missing).

3. **`test_playlist_description_meta_updated_on_release_change`** — Seed a release with tracks in a playlist. Modify a track's tags (e.g. change tracktitle). Run cache update (which should trigger playlist update). Assert the playlist's `description_meta` for that track reflects the new title.

4. **`test_same_path_release_replacement`** — Seed release A at a path. Delete release A's sidecar, create release B's sidecar at the same path (different UUID). Run cache update. Assert the old release is gone and the new one exists without a unique constraint violation.

## Tests to Write
4 new test functions. These are integration-level tests requiring the seeded test database fixture already used extensively in `cache.rs` tests.
