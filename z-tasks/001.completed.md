# Task 001: Create Cargo Workspace (M-1.1)

## Objective
Create the Cargo workspace scaffold for the Rose Rust migration with the `rose-core` library crate and all foundational dependencies.

## Context
Rose is a music library manager for Unix, currently implemented in ~11,400 lines of Python. We are migrating it to Rust for performance. This task creates the empty workspace that all subsequent tasks build upon.

## Constraints Relevant to This Task
- The crate layout must match the plan: workspace root at `rose-rs/`, library crate at `rose-rs/rose-core/`.
- `.gitignore` already ignores `rose-rs/target/`.
- Use `tracing` for logging (not `log`).
- Use `thiserror` for error types.

## Prior Work
None. This is the first task.

## Files to Read
- No Python files needed.
- Skim `rose-py/rose/common.py` (231 lines) to understand the error hierarchy that will be needed next.

## What to Implement

### 1. Workspace root `rose-rs/Cargo.toml`
```toml
[workspace]
resolver = "2"
members = ["rose-core"]
```

### 2. Library crate `rose-rs/rose-core/Cargo.toml`
Dependencies to include (with appropriate version pinning):
- `serde` (with `derive` feature)
- `sha2`
- `regex`
- `unicode-normalization`
- `tracing`
- `thiserror`

Dev dependencies:
- None yet (but leave room for `pretty_assertions` or similar).

### 3. Library crate `rose-rs/rose-core/src/lib.rs`
Create a minimal lib.rs that:
- Declares module stubs as comments (common, genre_hierarchy, audiotags, etc.) for documentation.
- Has a `pub const VERSION: &str` that reads from an environment variable or is hardcoded to match `rose-py/rose/.version`.

### 4. Verification
- Run `cargo build` from the workspace root.
- Run `cargo clippy` from the workspace root.
- Both must succeed with zero warnings.

## API to Produce
Just the workspace structure:
```
rose-rs/
  Cargo.toml              (workspace)
  rose-core/
    Cargo.toml
    src/
      lib.rs              (VERSION constant, module declarations)
```

### Design Decisions

- **Version hardcoded to `"0.5.0"`** to match the contents of `rose-py/rose/.version`. A build-script or `env!()` approach was considered but deemed unnecessary complexity at this stage; the version is also declared in `rose-core/Cargo.toml` so both stay in sync manually for now.
- **Module stubs listed as comments** rather than empty `mod` declarations to avoid creating placeholder files. This keeps the tree clean until each module is actually implemented.
- **`thiserror` v2** chosen (latest stable) since there is no existing Rust code to maintain compatibility with.
- **`sha2` pinned to `0.10`** (the `0.11` line exists but `0.10` is still widely used and matches the `digest 0.10` ecosystem).
- **Dev-dependencies section left empty** but present, ready for `pretty_assertions` or similar in future tasks.

### Deviations from Plan

None. Implementation matches the specification exactly.

### Known Issues / Tech Debt

- `VERSION` is duplicated between `Cargo.toml` (`version = "0.5.0"`) and `lib.rs` (`pub const VERSION`). A future task could unify these via `env!("CARGO_PKG_VERSION")`.
- No `Cargo.lock` is committed yet; consider committing it once the project stabilizes (Cargo recommends committing the lockfile for applications).
