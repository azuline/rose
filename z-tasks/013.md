# Task 013: Cache Filtered Queries (M-6.4)

## Objective
Implement `filter_releases` and `filter_tracks` — dynamic SQL query builders that support 8 filter dimensions with artist alias resolution and genre hierarchy expansion.

## Context
Rose is a music library manager being migrated from Python to Rust. The VFS and CLI use filtered queries to display releases/tracks by artist, genre, descriptor, label, release type, new/favorite status. These are the most complex read queries in the cache module.

## Constraints Relevant to This Task
- Artist alias resolution: expand filter artist to all transitive aliases via `Config.artist_aliases_map`.
- Genre hierarchy: expand genre filter to all transitive child genres via `TRANSITIVE_CHILD_GENRES`.
- SQLite PRAGMAs on every connection.
- Dynamic SQL construction — build WHERE clauses with parameterized queries (no string interpolation of user values).

### `filter_releases`
```rust
pub fn filter_releases(
    config: &Config,
    release_artist_filter: Option<&str>,
    all_artist_filter: Option<&str>,
    genre_filter: Option<&str>,
    descriptor_filter: Option<&str>,
    label_filter: Option<&str>,
    release_type_filter: Option<&str>,
    new: Option<bool>,
    favorite: Option<bool>,
    include_loose_tracks: bool,
) -> Result<Vec<Release>>
```

Build dynamic SQL starting from `SELECT * FROM releases_view rv WHERE 1=1`. For each non-None filter:
- `release_artist_filter`: resolve aliases, EXISTS subquery on `releases_artists`.
- `all_artist_filter`: resolve aliases, EXISTS on `releases_artists` OR EXISTS on `tracks_artists` (join through release_id). Note: Python line 1803–1816 has a bug where it queries `releases_artists` twice instead of also querying `tracks_artists` — reproduce this bug for now (match Python behavior).
- `genre_filter`: expand with `TRANSITIVE_CHILD_GENRES`, EXISTS on `releases_genres` OR `releases_secondary_genres`.
- `descriptor_filter`: EXISTS on `releases_descriptors`.
- `label_filter`: EXISTS on `releases_labels`.
- `release_type_filter`: direct WHERE on `releasetype`.
- `new` / `favorite`: direct WHERE on boolean columns.
- `include_loose_tracks=false`: exclude `releasetype = 'loosetrack'`.
- ORDER BY `source_path`.

### `filter_tracks`
```rust
pub fn filter_tracks(
    config: &Config,
    track_artist_filter: Option<&str>,
    release_artist_filter: Option<&str>,
    all_artist_filter: Option<&str>,
    genre_filter: Option<&str>,
    descriptor_filter: Option<&str>,
    label_filter: Option<&str>,
    new: Option<bool>,
    favorite: Option<bool>,
) -> Result<Vec<Track>>
```

Build dynamic SQL from `SELECT * FROM tracks_view tv WHERE 1=1`. Same filter logic but:
- `track_artist_filter`: EXISTS on `tracks_artists` with alias resolution.
- `release_artist_filter`: EXISTS on `releases_artists` (join on `release_id`).
- `all_artist_filter`: EXISTS on `tracks_artists` OR EXISTS on `releases_artists`.
- Genre/descriptor/label: EXISTS subqueries joined through `tv.release_id`.
- `new`/`favorite`: direct WHERE.
- After fetching track rows, batch-fetch releases into a HashMap, then construct `Track` objects.
- ORDER BY `source_path`.
