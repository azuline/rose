# Task 002: Port common.rs (M-1.2)

## Objective
Port the common utilities module from Python to Rust, including error types, the `Artist`/`ArtistMapping` types, filesystem sanitization functions, and helper utilities.

## Context
Rose is a music library manager being migrated from Python to Rust. The `common` module is the foundational grab-bag used by every other module. It contains types, error hierarchy, and utility functions.

## Constraints Relevant to This Task
- **Path normalization:** Do NOT normalize paths to NFC for comparison (match Python, which compares raw OS bytes). `sanitize_dirname`/`sanitize_filename` apply NFC on *output* only. Python has NFC normalization commented out in `_compare_strs()` (`cache.py:2535`).
- **Feature parity required:** Every capability in Python must exist in Rust.

## What to Implement

### Error types (`RoseError`)
Port as a `thiserror` enum. At minimum:
- `RoseError` with variants for expected errors (printed without traceback) and internal errors.
- Specific variants: `GenreDoesNotExist`, `LabelDoesNotExist`, `DescriptorDoesNotExist`, `ArtistDoesNotExist`.
- The Python pattern has `RoseExpectedError` as a subclass — model this with an `is_expected()` method or a trait.

### `Artist` struct
```rust

pub struct Artist {
    pub name: String,
    pub alias: bool,  // default false
}
```

### `ArtistMapping` struct
Fields: `main`, `guest`, `remixer`, `producer`, `composer`, `conductor`, `djmixer` — each `Vec<Artist>`.
Methods:
- `all(&self) -> Vec<&Artist>` — deduplicated union of all roles, preserving order (main, guest, remixer, producer, composer, conductor, djmixer).
- `dump(&self)` — serialize to a serde-compatible representation.
- `items(&self) -> Vec<(&str, &[Artist])>` — yields `("main", &self.main)`, etc.
- `Default` impl with empty vecs.

### `sanitize_dirname(max_filename_bytes: usize, name: &str, enforce_maxlen: bool, sanitize_diacritics: bool) -> String`
- Replace `ILLEGAL_FS_CHARS_REGEX` matches with `_`.
- If `enforce_maxlen`: truncate UTF-8 to `max_filename_bytes` bytes at a char boundary, then `.trim()`.
- If `sanitize_diacritics`: NFD decompose, strip combining chars.
- Always: NFC normalize the output.

### `sanitize_filename(max_filename_bytes: usize, name: &str, enforce_maxlen: bool, sanitize_diacritics: bool) -> String`
Same as `sanitize_dirname` but preserves file extension. If extension is >6 bytes, treat it as part of the stem.

### `sha256_dataclass` equivalent
`pub fn sha256_struct(value: &impl Serialize) -> String` — deterministic SHA-256 of a serde-serializable value. Use `serde_json::to_string` for canonical form, then SHA-256 the bytes.

### Utility functions
- `pub fn flatten<T>(xxs: Vec<Vec<T>>) -> Vec<T>`
- `pub fn uniq<T: Eq + Hash + Clone>(xs: Vec<T>) -> Vec<T>` — preserves first-occurrence order.

### Constants
- `pub const VERSION: &str = "..."` — match the value in `rose-py/rose/.version`.
- `pub static ILLEGAL_FS_CHARS_REGEX: Lazy<Regex>` — pattern: `[:\?<>\\*\|"\/]+`

## Tests to Write
1. **Illegal chars:** `sanitize_dirname` replaces `:?<>\\*|"/` with `_`.
2. **Max-length truncation:** Truncate at byte boundary (e.g., a multi-byte char at boundary 180 must not produce invalid UTF-8).
3. **Diacritics stripping:** `"Modéré"` with `sanitize_diacritics=true` becomes `"Modere"`.
4. **NFC output:** Output is always NFC-normalized.
5. **Empty input:** `sanitize_dirname("", ...)` returns `""`.
6. **Extension preservation:** `sanitize_filename("foo:bar.mp3", ...)` keeps `.mp3`.
7. **Long extension ignored:** Extensions >6 bytes are treated as part of the stem.
8. **`ArtistMapping::all()` dedup:** Artists appearing in multiple roles appear only once in `all()`.
9. **Hash determinism:** Same struct produces same hash across calls.
10. **`uniq` preserves order:** `[3, 1, 2, 1, 3]` -> `[3, 1, 2]`.
