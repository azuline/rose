# Task 045: Expose Read Operations to Python (M-14.2)

## Objective
Expose cache read operations and data types from `rose-core` to Python via PyO3, enabling Python scripts to query releases, tracks, collages, playlists, artists, genres, labels, and descriptors.

## Context
Rose is a music library manager being migrated from Python to Rust. The PyO3 crate `rose-rs/rose-py/` was created in the prior task (044) with `Config` exposed. This task adds wrapper types for all domain entities and read/query functions so Python scripts can fully inspect the library.

## Constraints Relevant to This Task
- All wrapper types use `#[pyclass]` with readable attributes (`#[pyo3(get)]`).
- Don't expose every internal field — expose what's useful for scripting: identifiers, names, metadata, paths. Omit internal hashes and mtime fields.
- Functions that take `Config` should accept `&PyConfig` and extract the inner `Config`.
- `update_cache` must be exposed since it's needed before any reads return data.

## Prior Work
The `rose-py` crate exists at `rose-rs/rose-py/` with:
- `PyConfig` wrapper for `rose_core::Config` (`#[pyclass(name = "Config")]`)
- Module named `rose` with `Config` registered.

## What to Implement

All additions in `rose-rs/rose-py/src/lib.rs` (or split into submodules if cleaner).

1. **Wrapper types** — each wraps a `rose-core` struct:
   - `PyRelease` (`#[pyclass(name = "Release")]`): `id`, `releasetitle`, `releasedate` (as Option<String>), `originaldate`, `edition`, `catalognumber`, `releasetype`, `genres` (Vec<String>), `secondary_genres`, `labels`, `descriptors`, `new` (bool), `favorite` (bool), `rating` (Option<i32>), `disctotal`, `source_path` (String).
   - `PyTrack` (`#[pyclass(name = "Track")]`): `id`, `tracktitle`, `tracknumber`, `discnumber`, `duration_seconds`, `source_path` (String), and a `release` getter returning `PyRelease`.
   - `PyCollage` (`#[pyclass(name = "Collage")]`): `name`.
   - `PyPlaylist` (`#[pyclass(name = "Playlist")]`): `name`, `cover_path` (Option<String>).
   - `PyArtist` or expose artists as dicts/lists — choose the simplest ergonomic form.

2. **Module functions:**
   - `update_cache(config: &PyConfig) -> PyResult<()>`
   - `list_releases(config: &PyConfig) -> PyResult<Vec<PyRelease>>`
   - `list_tracks(config: &PyConfig) -> PyResult<Vec<PyTrack>>`
   - `list_collages(config: &PyConfig) -> PyResult<Vec<PyCollage>>`
   - `list_playlists(config: &PyConfig) -> PyResult<Vec<PyPlaylist>>`
   - `list_artists(config: &PyConfig) -> PyResult<Vec<String>>`
   - `list_genres(config: &PyConfig) -> PyResult<Vec<String>>`
   - `list_labels(config: &PyConfig) -> PyResult<Vec<String>>`
   - `list_descriptors(config: &PyConfig) -> PyResult<Vec<String>>`
   - `get_release(config: &PyConfig, id: &str) -> PyResult<Option<PyRelease>>`
   - `get_track(config: &PyConfig, id: &str) -> PyResult<Option<PyTrack>>`
   - `get_collage(config: &PyConfig, name: &str) -> PyResult<Option<PyCollage>>`
   - `get_playlist(config: &PyConfig, name: &str) -> PyResult<Option<PyPlaylist>>`

3. **Register all new classes and functions** in the `rose` pymodule.

## Tests to Write
1. `cargo build -p rose-py` succeeds.
2. Python: `import rose; c = rose.Config.load(...); rose.update_cache(c)` runs without error.
3. Python: `releases = rose.list_releases(c)` returns a list; each element has `.id`, `.releasetitle`.
4. Python: `r = rose.get_release(c, some_id)` returns a Release or None.
5. Python: `tracks = rose.list_tracks(c)` returns a list with `.tracktitle` accessible.
